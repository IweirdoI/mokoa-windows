## 一、下载麒麟系统前已完成的事项

- preference 与 knowledge 两条功能分支已经进入主线；
- 编排核心已经接入偏好自动提取、版本链、长期存储公开接口、召回和级联遗忘；
- 开发测试内存后端与真实 Milvus 后端已经显式拆开；
- 开发环境不启动 Milvus 时 API 仍可启动，但日志明确标注“不代表真实验收”；
- PyMilvus 约束在 2.x，避免 3.x 对 protobuf 和接口兼容性的影响；
- 项目存储环境变量改为 `OS_AGENT_MILVUS_URI`，避免与 PyMilvus 自身的 `MILVUS_URI` 冲突；
- Embedding 支持 `auto`、`kylin`、`local`、`hash` 四种明确模式；
- 麒麟适配器支持严格模式，验收时禁止降级；
- ctypes 能自动尝试动态库发现，也支持显式指定 `.so`；
- 已提供预检、离线端到端和真实 SDK smoke test；
- 已提供麒麟环境变量模板。

## 二、当前立即可运行的检查

### 1. 当前开发环境端到端接线

```bash
python scripts/smoke_e2e.py
```

必须输出 `"passed": true`。该检查使用内存存储和确定性 Hash 向量，只证明：

- 偏好规则提取可调用；
- 偏好可以进入统一存储入口；
- 同 key 新值形成版本替换；
- 历史版本和最新版本查询可用。

它不证明真实 Milvus、麒麟 SDK、召回率或 500ms 指标。

### 2. 生成当前机器预检报告

```bash
python scripts/kylin_preflight.py --output data/reports/preflight.json
```

Windows 下 `ready_for_kylin_runtime=false` 是预期结果。脚本仍会检查Python版本、CPU架构、PyMilvus和项目后端配置。

### 3. 回归测试

```bash
python -m pytest -q \
  tests/test_kylin_readiness.py \
  tests/test_knowledge.py \
  tests/test_config.py \
  tests/test_preference_orchestrator_wire.py \
  tests/test_api.py::test_health
```

## 三、下载并安装麒麟后按顺序执行

### 第一步：确认系统

优先使用赛题开发手册对应的银河麒麟 2503。执行：

```bash
uname -a
uname -m
cat /etc/os-release
python3 --version
```

记录系统版本、CPU架构和Python版本。推荐Python 3.10～3.12。

### 第二步：安装AI子系统和SDK

1. 打开“设置 → AI模块管理”，下载安装AI子系统；
2. 安装Embedding开发包：

```bash
sudo apt update
sudo apt install libkylin-coreai-embedding-dev
```

3. 验证安装：

```bash
pkg-config --modversion kysdk-coreai-embedding
ldconfig -p | grep -i 'coreai.*embedding'
dpkg-query -W libkylin-coreai-embedding-dev
```

如果实际包名或pkg-config名称不同，以目标系统apt搜索结果和开发包文件列表为准，并记录到测试报告。

### 第三步：建立独立Python环境

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

不要直接污染系统Python。

### 第四步：运行预检

```bash
python scripts/kylin_preflight.py \
  --require-kylin \
  --output data/reports/kylin_preflight.json
```

必须达到：

- `linux=true`；
- `supported_arch=true`；
- `kylin_embedding_sdk_detected=true`；
- `pymilvus=true`；
- `ready_for_kylin_runtime=true`。

### 第五步：严格验证真实Embedding SDK

```bash
export OS_AGENT_EMBEDDING_BACKEND=kylin
export OS_AGENT_KYLIN_STRICT=1
python scripts/smoke_kylin_embedding.py \
  --runs 20 \
  --output data/reports/kylin_embedding.json
```

验收要求：

- `passed=true`；
- `backend=kylin-coreai`；
- `using_fallback=false`；
- 向量非零且维度一致；
- 相近语句相似度高于无关语句；
- 记录min/median/max延迟。

如果自动找不到动态库：

```bash
export KYLIN_EMBEDDING_LIBRARY=/实际路径/libkysdk-coreai-embedding.so
```

再运行严格测试。禁止关闭严格模式后把降级结果作为验收结果。

### 第六步：确认向量维度后初始化Milvus

先读取 `kylin_embedding.json` 中的真实 `dimension`，再设置：

```bash
export MEMORY_VECTOR_DIM=<真实维度>
export OS_AGENT_MEMORY_BACKEND=milvus
```

小规模演示优先尝试Milvus Lite：

```bash
export OS_AGENT_MILVUS_URI=./data/os_agent_memory.db
```

若目标麒麟环境无法安装Lite依赖，则使用Standalone/Docker Milvus：

```bash
export OS_AGENT_MILVUS_URI=http://127.0.0.1:19530
```

注意：改变向量维度后不能继续使用旧Collection，必须创建新Collection或清理测试库后重新初始化。

### 第七步：启动真实服务

```bash
export OS_AGENT_MEMORY_BACKEND=milvus
export OS_AGENT_EMBEDDING_BACKEND=kylin
export OS_AGENT_KYLIN_STRICT=1
uvicorn api.server:app --host 127.0.0.1 --port 8000
```

另一终端检查：

```bash
curl http://127.0.0.1:8000/health
```

### 第八步：真机全链验收

必须验证：

1. `/preferences/extract` 能自动提取偏好；
2. `/preferences/{user_id}?latest_only=false` 能看到版本历史；
3. `/recall` 使用真实向量返回相关结果和score；
4. 服务重启后数据仍然存在；
5. `/forget` 后短期、中期、长期均不可召回；
6. 端到端检索延迟不超过500ms；
7. 报告明确记录机器、系统、CPU、内存、SDK、模型、向量维度、Milvus模式和数据规模。

## 四、模式说明

| 模式 | 环境变量 | 用途 | 可否作为比赛验收 |
|---|---|---|---|
| 内存 + Hash | `memory` + `hash` | 快速接线、单元测试 | 否 |
| 内存 + BGE-M3 | `memory` + `local` | Windows功能演示 | 否 |
| Milvus + BGE-M3 | `milvus` + `local` | 存储联调 | 只能验证Milvus，不能验证麒麟SDK |
| Milvus + Kylin strict | `milvus` + `kylin` + strict | 正式真机验收 | 是 |
