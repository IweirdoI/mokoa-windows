## 三、与最新测试结果不符（需修正）

### ❌ 1. 第 28 页「MS MARCO 默认召回 103.0ms」
- PDF 原文第 28 页 9.3.3 延迟表列出：`MS MARCO 纯语义 108.6ms`、`MS MARCO 默认召回 103.0ms`、`MS MARCO 组件检索 169.6ms`。
- 证据 JSON 中 MS MARCO 三策略 P95 分别为 **108.611（query_memory/纯语义）/ 109.342（orchestrator_recall/编排）/ 124.216（orchestrator_semantic）**，**不存在 103.0**。
- 修订稿 9.3.3 表与抽测报告均写 **109.3ms（编排 P95）**。
- 结论：陈旧/错误数字，应改为 **109.3ms**（对应 orchestrator_recall）或 108.6ms（纯语义）。

### ❌ 2. 第 28 页「TREC Recall@5 = 0.1591」
- PDF 原文第 28 页：`TREC DL Recall@5 97问/7707段 0.1591`。
- 证据 JSON 三种 TREC 策略 `recall_at_5` 全部 = **0.158**（`trec.*.recall_at_5 = 0.158`）。
- 结论：应为 **0.158**，PDF 多写一位。

- **TREC 段数 7707**：PDF 写 7707，证据 `n_positive_passage_ids = 7707` 正是此值（judged 正例段落数）；报告里写的 9707 实为 `corpus_size`（7707 正例 + 2000 reservoir 干扰）。PDF 无误。
