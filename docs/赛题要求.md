### 本次优化要点

1. **知识冲突处理正确率（原缺口）**
   - 旧实现：`resolve_knowledge()` 直接 `TODO` 透传来源等级判定，导致手动配置（trust=3）永远压过对话（trust=2），即使对话给出更新鲜的事实（如「端口 8080 → 9090」）也会被旧手动配置压住 → 知识冲突正确率被系统性压低。
   - 修复：改为「**知识取最新事实**」语义，新事实更新鲜时默认 REPLACE；仅当低信任观测（behavior / tool_result）试图覆盖更高信任旧事实（conversation / manual_config）时保留 KEEP_OLD。
   - 新增独立金标准 `benchmarks/datasets/conflict_resolution.jsonl`（22 条，覆盖偏好漂移、手动配置权威、跨场景不冲突、知识最新事实胜出、低信任不覆盖等），评测脚本 `scripts/conflict_eval_dataset.py` 产出可复现正确率。

2. **知识检索召回率（历史夸大问题）**
   - 旧评测子库由各问正例互为干扰，无真实负例 → Hit@1 被放大。
   - 修复：`--rc` 语义改为「从 8.8M 全库 reservoir 抽样的随机干扰段数量」，确保子库含真实随机负例（详见 `docs/RETRIEVAL_EVAL_FIX.md`）。

3. **知识检索响应时间（历史破线问题）**
   - 旧默认 `auto` 路径对英文开放域查询仍触发词面补召（1 万级全表扫描）→ P95 = 1005ms 破线。
   - 修复：英文查询默认走语义排序（`is_likely_english` 跳过词面补召），P95 降至 386ms。

4. **偏好提取准确率（历史缺口：从未跑出可报数字）**
   - 金标准 `benchmarks/datasets/preference_extraction.jsonl`（35 条：原句/同义/英文/版本链/跨场景/负例）与评测脚本 `scripts/pref_eval_dataset.py` 已就绪。
   - 本次实测（rule 模式，离线可复现）：**精确率 100% / 召回率 95.83% / 样本完全匹配率 94.29%**，5 条负例零误报 → 达 ≥ 85% 目标。仅 2 条改写/英文复述样本漏召回第二键，不影响过线。
