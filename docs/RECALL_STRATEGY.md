# 关联检索策略

检索顺序保持为向量候选 → 主题扩展补召 → 词面候选 → 项目隔离 → 主题排序。
所有补召沿用用户、场景和最新版本过滤条件。`latency_ms` 现在统计完整
`recall()` 耗时，包含补召、词面扫描和重排，不再只统计首轮向量查询。

本次调整：

- `默认` 单独出现不触发偏好意图；下载路径、语言、明确喜好仍按偏好处理。
- 用端口、健康检查、负责人、打印机、装包等中英主题组进行扩展和评分。
  一个主题只计一次；英文按词边界匹配，`port` 不会命中 `support`。
- 从记忆中的项目元数据、`Project:`、`FACT project=` 和双语标题建立别名关联。
  允许空格/连字符差异，不在实现中写入演示项目名或端口答案。
  项目别名只用于范围约束，移出主题评分；正文顺带提到另一项目不覆盖明确归属。
- 知识查询优先相关知识，避免配置路径偏好抢占答案。缺少主题证据时可返回空，
  不再因为候选是英文或属于同一项目就一概保留。

验证：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_recall_strategy.py tests/test_retrieval_crosslang.py tests/test_core.py -q
```

新测试走真实 `recall()` / `query_memory()` / 内存检索后端，只有 embedding
替换为确定性向量，刻意用 25 条高分噪声挤掉目标文档。覆盖换说法、英文文档、
双语项目、偏好干扰、旧版本与跨用户/场景隔离、无关问题返回空。

边界：主题词表不是通用语义理解；没有双语关联证据时不会猜测项目译名。
词面池仍沿用最多 10,000 条的扫描上限，大库召回与扫描成本需要后续索引化处理。
本地测试不代表真实麒麟环境的 Recall@5 或 500 ms 指标，需在麒麟重新运行
KNOW/DOC/CONF 覆盖集验证。旧手册与更新通知的事实冲突继续依赖入库版本标记，
排序器不会仅凭正文中的新旧字样替代事实版本管理。
