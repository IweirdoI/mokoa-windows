## 一、先给结论

1. **赛题不是要求我们修改麒麟操作系统内核，也没有明确要求修改一个已经提供源码的“麒麟原生智能体”。**赛题要求的是开发一套“应用于麒麟操作系统 OS Agent 的多源融合偏好与知识记忆优化解决方案”，成果能够接入 OS Agent 或同类 Agent 产品。我们的正确定位是：**OS Agent 的可插拔记忆服务/记忆中间件**。
2. **项目不建议只用 Docker 交付。**赛题明确要求调用银河麒麟端侧 Embedding SDK，而 SDK 依赖宿主机的银河麒麟 2503、AI 子系统和 apt 安装的本地动态库。把所有组件都放进普通 Docker 容器，会增加调用宿主机 AI 子系统、动态库和 D-Bus 服务的难度。
3. 推荐采用 **“宿主机原生记忆服务 + 可选容器化存储 + Web/桌面演示入口”**：
   - Python/FastAPI 记忆服务原生运行于银河麒麟，通过 `systemd` 管理；
   - Embedding 适配器在宿主机直接调用麒麟 SDK；
   - Milvus 可根据目标机器资源选择 Milvus Lite（优先）或 Docker Milvus；
   - 前端以本地 Web 页面呈现，后续可增加 `.desktop` 启动入口；
   - 对外通过 HTTP API 提供给任意 OS Agent 调用。
4. 当前各成员的模块开发已接近阶段性完成，下一阶段应从“各自写功能”转为 **合并、联调、麒麟适配、指标验收和演示交付**。
5. 截至 2026-08-10，26a9835a的 `origin/feature/preference` 和cb0aeabe的 `origin/feature/knowledge` **均未合入 `master`**。建议从现在起冻结大功能开发，在 **1～3 个工作日内完成选择性迁移、联调和合并**，而不是直接把旧分支整体硬合进主线。
6. 麒麟系统安装好之后，不应该再补基础功能；届时主要完成 AI 子系统和 SDK 安装、真实 SDK 调用、系统兼容性修复、端侧性能测试与最终打包。

## 二、赛题究竟让我们做什么

### 2.1 赛题原文可以确定的内容

赛题将问题定义为：麒麟操作系统 OS Agent 的偏好记忆与知识记忆存在多源数据质量、偏好动态提取、版本管理、知识冲突和关联检索等问题。要求开发一套应用于麒麟操作系统 OS Agent 的解决方案，包含：

- 多源数据统一接入、清洗、标准化和质量校验；
- 偏好自动提取、版本化、跨场景适配与回溯；
- 知识结构化、冲突处理、关联检索和智能调用；
- 调用银河麒麟国产桌面操作系统 Embedding SDK；
- 轻量化端侧部署，知识检索响应时间不超过 500ms；
- 敏感信息识别、过滤和自然语言精准遗忘；
- 与短期、中期记忆的数据流转兼容；
- 通过标准化数据集形成完整量化测试报告。

评分还特别看重：技术创新性、方案可行性、端侧轻量化、量化指标、与 OS Agent 的适配性，以及软件功能实现的完整性。

### 2.2 不应过度解读的地方

赛题材料没有提供以下内容：

- 麒麟某个原生 OS Agent 的源码仓库；
- 要求修改操作系统内核或桌面环境；
- 指定必须把记忆模块嵌入某个固定进程；
- 指定必须使用 Docker、Deb 包或应用商店交付；
- 一套已经固定的 OS Agent 插件协议。

因此，我们不能把目标描述为“直接优化一个已经拿到源码的麒麟原生智能体”。更准确的表述是：

> 我们实现的是一个面向麒麟 OS Agent 的独立记忆能力层。上层 Agent 把对话、工具执行结果、用户行为和配置传给记忆服务；记忆服务完成提取、分层、存储、检索、冲突消解和遗忘，再把相关记忆返回给 Agent，供其生成回复或执行工具时使用。

### 2.3 我们在操作系统里的位置

推荐系统关系如下：

```text
银河麒麟桌面操作系统
├─ AI 子系统 / AI 模块管理
│  ├─ 端侧模型
│  ├─ Embedding SDK
│  └─ 可选文本生成 SDK
│
├─ 麒忆智脑 Memory Service（我们的核心成果）
│  ├─ 多源数据接入
│  ├─ 偏好提取与版本管理
│  ├─ 短期 / 中期 / 长期记忆编排
│  ├─ 敏感信息过滤与精准遗忘
│  ├─ 向量化适配层（调用麒麟 Embedding SDK）
│  └─ 记忆检索 API
│
├─ 本地存储
│  ├─ SQLite：接入审计、中转与轻量元数据
│  └─ Milvus Lite / Milvus：长期向量记忆
│
├─ 上层 OS Agent 或同类 Agent
│  └─ 通过 HTTP API 调用记忆写入、召回和遗忘
│
└─ 演示入口
   ├─ 本地 Web 前端
   └─ 可选 .desktop 桌面快捷方式
```

这既符合“应用于 OS Agent”的要求，又不依赖一个目前没有提供的私有 Agent 插件接口。

## 三、麒麟系统现有工具包中，哪些能用于本项目

银河麒麟开发手册的 AI SDK 部分以银河麒麟 2503 为前提：用户先在“设置 → AI 模块管理”中下载安装 AI 子系统，再通过 apt 安装具体 SDK。手册同时说明端侧能力目前主要适配 x86 和 ARM，且列出的已验证机型有限。因此，最终必须在实际比赛机器上重新验证，不能仅凭 Windows 开发环境结果声称完成适配。

### 3.1 必须使用：文本向量化 SDK

安装包：

```bash
sudo apt install libkylin-coreai-embedding-dev
```

主要头文件和接口：

```c
#include <coreai/embedding/embedding.h>

TextEmbeddingSession *text_embedding_create_session();
int text_embedding_init_session(TextEmbeddingSession *session);
bool text_embedding(
    TextEmbeddingSession *session,
    const char *text,
    EmbeddingResult **result
);
void text_embedding_async(
    TextEmbeddingSession *session,
    const char *text,
    TextEmbeddingResultCallback callback,
    void *callback_user_data
);
```

结果接口可以取得向量数组、向量长度、错误码和错误信息。该 SDK 应直接接入我们现有的 `src/embedding/embedding_interface.py`，由统一适配器隐藏 C 接口细节，上层存储和检索模块不能各自重复调用 SDK。

建议落地方式：

- Python 使用 `ctypes` 或一个很薄的 C/C++ 封装层调用动态库；
- 进程启动时创建并初始化会话，不要每次请求重新初始化；
- 单会话任务会串行执行，需要并发时建立有限大小的会话池；
- 对初始化失败、连接失败、运行时失败建立明确错误码和降级策略；
- 获取真实向量维度后再冻结 Milvus Collection Schema；
- 用相同 SDK 生成入库向量和查询向量，避免维度或模型不一致。

这是赛题点名要求的能力，优先级为 P0。

### 3.2 可选使用：文本生成 SDK

安装包：

```bash
sudo apt install libkysdk-genai-nlp-dev
```

手册说明它支持文本生成、文本对话、系统提示词，以及云端、端侧和自定义模型；模型可在“设置 → AI 模块管理”中配置。

它可用于：

- 偏好提取中的语义解析；
- 自然语言遗忘指令解析；
- 复杂知识冲突的语义判断；
- 演示一个真正调用麒麟 AI 子系统的端侧 Agent 场景。

但它不是赛题明确点名的硬要求，建议作为 P1 增强项。主流程必须保留规则或其他模型降级，不能因为文本生成 SDK 不可用而导致记忆系统整体不可运行。

### 3.3 可选使用：OCR SDK

手册提供两套相关能力：系统 SDK 的 OCR，以及 AI 子系统的文字识别 SDK。AI 子系统版本安装示例为：

```bash
sudo apt install libkysdk-coreai-vision-dev
```

适合扩展的场景：

- 从截图、扫描件和图片文档提取内容并进入知识记忆；
- 演示“多源数据”不仅包括文本和工具结果，也包括桌面截图；
- 为办公自动化场景构建图片知识沉淀。

OCR 不属于当前最小闭环，建议在主链、指标和前端完成后再做，不要抢占 Embedding、Milvus 和合并联调时间。

### 3.4 可选使用：语音识别/合成 SDK

手册中的语音 SDK 支持语音识别和合成，但该版本说明主要依赖云端服务，端侧支持有限。可用于语音输入偏好、语音遗忘命令或助手播报，但不建议作为当前比赛主线。

### 3.5 可用于真实 OS Agent 数据源：系统能力 SDK

手册还提供一批非 AI 系统能力，可作为“用户行为、工具结果、系统状态”的真实数据来源：

- 文件监听：捕捉文件创建、修改等行为，形成工作流程或项目上下文记忆；
- 系统信息、运行时信息：形成设备和运行环境上下文；
- 网络、存储、进程、设备信息：作为 OS Agent 工具调用的结构化结果；
- 日志模块：统一记录服务运行、SDK错误和性能数据；
- 配置文件、GSettings、统一配置：保存开关、后端选择和用户偏好；
- D-Bus 接口：与桌面、系统设置和部分系统服务交互；
- 搜索模块：手册标注部分版本未启用，必须在实际系统确认后才能采用。

建议本阶段只选择 **文件监听 + 系统信息** 做一项真实麒麟场景演示，不要一次接入所有系统 SDK。

### 3.6 本项目的采用优先级

| 优先级 | 能力 | 是否进入当前主线 | 用途 |
|---|---|---|---|
| P0 | 文本 Embedding SDK | 必须 | 记忆入库和语义检索，赛题硬要求 |
| P0 | AI 子系统 / AI 模块管理 | 必须 | 提供端侧模型和 SDK 运行环境 |
| P1 | 文本生成 SDK | 建议试接 | 偏好提取、冲突判断、NL 遗忘 |
| P1 | 文件监听或系统信息 SDK | 选择一个 | 证明系统级多源接入和 OS Agent 适配 |
| P2 | OCR SDK | 可选 | 图片/截图知识接入 |
| P2 | 语音 SDK | 暂缓 | 语音输入和播报 |

## 四、服务应以什么形式部署

### 4.1 推荐的正式方案：混合原生部署

#### A. 宿主机原生组件

以下组件原生运行在银河麒麟：

- `api/server.py` 启动的 FastAPI 服务；
- Memory Orchestrator 和各业务模块；
- 麒麟 Embedding SDK 适配器；
- SQLite 中转库；
- 前端静态资源或本地 Web 服务。

使用 `systemd` 管理，例如最终可形成：

```text
kylin-memory.service
```

它负责：开机启动、异常重启、日志查看、运行用户和环境变量管理。

#### B. 存储组件

存储有两档：

1. **优先方案：Milvus Lite**  
   更适合单机、端侧、演示和轻量化论证，安装与部署简单。需要先验证当前 pymilvus 版本和目标架构是否支持。
2. **兼容方案：Docker Milvus**  
   如果目标机器已具备 Docker/Compose，且资源允许，可以只把 Milvus 容器化。业务服务和麒麟 SDK 适配器仍留在宿主机。

#### C. 展示和调用入口

- 评委通过浏览器打开本地前端；
- OS Agent 通过 `127.0.0.1` 上的 HTTP API 调用；
- 可增加 `.desktop` 文件，双击启动或打开演示页面；
- 后续若得到官方 Agent 插件协议，只需新增适配器，不改记忆核心。

### 4.2 为什么不建议全量 Docker

全量 Docker 的问题包括：

- 容器默认无法直接使用宿主机 AI 子系统；
- 需要额外挂载麒麟 SDK 动态库和依赖；
- 可能需要访问宿主机 D-Bus socket；
- 不同 CPU 架构的镜像需要分别构建；
- 容器调用宿主机端侧模型的性能与权限需要额外验证；
- 容易削弱“轻量端侧部署”的论证。

因此 Docker 的正确定位是：

> 可用于开发环境复现、可选的 Milvus 部署和后续服务器版交付，但不是调用麒麟端侧 SDK 的唯一正式运行方式。

### 4.3 用户部署、容器、镜像和下载应如何理解

会议中提到的内容可以整理为三个不同交付层次：

#### 开发人员部署

- 克隆源码；
- 安装银河麒麟 AI 子系统；
- apt 安装 SDK 开发包；
- 建立 Python 虚拟环境并安装依赖；
- 启动 Milvus Lite 或 Docker Milvus；
- 启动后端和前端。

#### 评委/普通用户部署

理想方式是提供一个安装脚本或 Deb 包，完成：

- 检查系统版本和 CPU 架构；
- 检查 AI 子系统是否已安装；
- 安装/检查麒麟 SDK；
- 安装项目文件和 Python 环境；
- 初始化数据目录；
- 注册 `systemd` 服务；
- 创建桌面快捷方式；
- 执行健康检查。

普通用户不应该手动进入源码目录逐条运行命令。

#### 镜像交付

如果团队说的“镜像”是 Docker 镜像，应至少说明：

- 镜像只包含哪些服务；
- 是否包含 Milvus；
- 如何访问宿主机 Embedding SDK；
- x86 和 ARM 是否分别构建；
- 数据目录如何持久化。

如果“镜像”指已经配置好的麒麟虚拟机镜像，则更适合比赛快速复现，但不能替代源码、安装脚本和文档交付。

### 4.4 建议最终同时提供的交付物

1. 源代码；
2. 一键安装脚本；
3. 一键启动/停止脚本；
4. `systemd` 服务文件；
5. 可选 Milvus Docker Compose；
6. 示例配置文件；
7. 演示种子数据；
8. 健康检查脚本；
9. 测试报告；
10. 使用说明和开发者接入说明。

### 5.4 正确的合并方式

建议：

1. 从最新 `master` 新建临时集成分支；
2. 只迁移各功能分支中属于本模块的源码、测试、数据集和必要依赖；
3. 不迁移 `__pycache__`、本地运行数据、个人配置和过时公共文件；
4. 公共接口冲突以当前 `master` 为基线重新适配；
5. preference 和 knowledge 分别形成可审查的两个合并提交或 PR；
6. 每合入一个模块立即跑对应测试；
7. 两者都完成后再跑全链测试。

不建议：

- 直接把两个旧分支依次 merge 到 `master`；
- 为了减少冲突而覆盖主线文件；
- 在没有测试结果的情况下把“代码已合并”等同于“功能已完成”。

### 5.5 合并验收门槛

26a9835a模块合并通过至少满足：

- 自然语言输入可以产出统一 `MemoryEntry`；
- 正例能提取、负例不会明显误提取；
- 同 key 更新形成 v1 → v2；
- 35 条数据集可执行；
- 不依赖个人密钥也能运行规则降级；
- 不提交缓存、密钥和运行数据。

cb0aeabe模块合并通过至少满足：

- 使用真实 Milvus/Milvus Lite，不只使用进程内 Mock；
- 服务重启后数据仍然存在；
- 写入和查询使用同一 Embedding 接口；

- Milvus 不可用时错误可观察，不静默伪装成功。

## 十、材料依据与注意事项

### 10.1 赛题材料依据

- 《XA-202612 麒麟软件有限公司 - OS Agent 记忆优化及高效应用研究比赛方案》：重点参考题目背景、需求分析、题目内容第（1）～（7）项及评分标准。
- 赛题明确写明调用银河麒麟国产桌面操作系统 Embedding SDK、适配端侧部署、采用轻量化存储并保证检索延迟不超过 500ms。
- 赛题没有指定 Docker、Deb 包或某个固定 Agent 插件协议，因此本文的部署形态属于结合要求和当前项目做出的工程建议。

### 10.2 麒麟开发手册依据

- 《kylinos_dev_manual(1)》第 9.2 节：银河麒麟 2503、AI 子系统、apt 安装部署和已适配机型说明；
- 第 9.3 节：会话创建、初始化、串行任务与多会话并发；
- 第 9.4.3 节：文本/图像向量化、同步/异步接口、结果解析和错误码；
- 第 9.5.1 节：文本生成、文本对话、系统提示词，以及云端、端侧、自定义模型配置；
- 其他章节：文件监听、系统信息、日志、配置、D-Bus、OCR 和语音等系统能力。

### 10.3 最重要的风险提示

- 手册描述的是特定系统和 SDK 版本，实际包名、pkg-config 名称、动态库路径可能随镜像版本变化，必须以目标系统 `apt` 和 `pkg-config` 实测为准；
- 手册只列出有限已适配机型，不能据此保证所有国产 CPU 和显卡均可运行；
- 当前项目的 Windows BGE-M3 或 Hash fallback 只能用于开发和回归，不能替代赛题要求的银河麒麟 Embedding SDK 验收；
- 使用真实 SDK 后向量维度可能变化，Milvus Schema 不应在未探测真实维度时永久写死；
- “已写代码”“已合并”“已通过单元测试”“已在麒麟端侧验收”是四个不同状态，汇报时必须区分。
