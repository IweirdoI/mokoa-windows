## 1. 结论

项目的麒麟 Embedding SDK、核心 Python 测试、偏好提取、画像和版本历史已经能够在银河麒麟 V11 上运行，但本轮尚不能判定为“完全满足比赛要求”。

主要原因：

1. 真实麒麟 Embedding SDK 已通过严格验证；
2. 四项比赛指标的现有测试通过，但检索召回和检索耗时使用进程内向量后端，只能算组件基线，不能替代真实 Milvus 正式成绩；
3. 冲突更新存在画像与权威检索结果不一致；
4. 自然语言精准遗忘在真实 HTTP 演示中未删除目标记忆；
5. 虚拟机未安装 Node.js/npm，前端尚未在 V11 上完成构建和浏览器联调；
6. 尚缺比赛提交所需的标准化数据集正式跑分、对比实验和完整适配测试材料。

## 5. 真实 FastAPI HTTP 演示

FastAPI 使用以下关键配置临时启动：

```bash
export OS_AGENT_MEMORY_BACKEND=memory
export OS_AGENT_EMBEDDING_BACKEND=kylin
export OS_AGENT_KYLIN_STRICT=1
export KYLIN_EMBEDDING_LIBRARY=/lib/x86_64-linux-gnu/libkysdk-coreai-embedding.so.1
python -m uvicorn api.server:app --host 127.0.0.1 --port 18080
```

### 5.1 已通过

- `GET /health` 返回 `status=ok`；
- 从“下载默认放 D 盘”提取 `habit.download_path=D:/Downloads`；
- 从“以后下载改到 E 盘”生成版本 2；
- 偏好画像返回 `habit.download_path=E:/Downloads`；
- 版本历史保留 D 盘版本 1 和 E 盘版本 2；
- `/recall` 完成真实麒麟 Embedding 调用，HTTP 链路耗时约 37.18ms，低于 500ms。

### 5.2 发现的问题

#### P0：冲突更新后画像与权威检索不一致

第二次更新返回：

```text
created=false
reason=旧记忆更可信或更新
```

但本地偏好画像已经切换为 E 盘；随后 `/recall` 仍返回 D 盘旧记忆。需要统一“版本索引更新”和“权威存储冲突决策”的事务边界，避免界面展示与 Agent 实际召回不一致。

#### P0：自然语言精准遗忘未生效

请求“忘掉下载路径偏好”后返回：

```json
{"count": 0, "deleted_ids": []}
```

当前自然语言指令尚未正确解析到 `habit.download_path` 对应记忆 ID，不符合比赛第（5）项“自然语言指令驱动的精准遗忘操作”。
