# 语义化版本打标记录（20260915-2338，增量补标）

## 背景

按 SemVer 规范用 `scripts/auto_tag_semver.py` 为 `master` 历史提交批量打标。上一轮打标记录在
`docs/语义化版本打标记录_20260915-1249.md`，当时打到的最后一个版本为 `0.53.2`（提交 `71855ab`）。
本轮把 2026-09-15 下午至夜间新产生的提交补标。

## 本轮发现并修复的脚本缺陷

原脚本在两种情况下会出错，均已修复（`scripts/auto_tag_semver.py`）：

1. **旁支提交撞名被静默跳过**：提交 `590f6c5` 在拓扑序里排在 `dfe3010`（已有标签 `0.53.1+build.2`）之前，
   脚本给它算出的标签名与已有标签重名，被"跳过已存在标签"的逻辑直接丢弃，导致该提交**永远打不上标签**，
   且后续编号整体错位。
   修复：新增 `read_existing_tags()`（通过 `git for-each-ref` 取"标签名 → 提交 sha"映射），
   `build_plan()` 在算出的 `+build.N` 标签被**其他**提交占用时继续递增编号直到空闲。
2. **已打标提交被重复编号**：上面第 1 点错位后，已打标的 `dfe3010` 又被规划出一个新号 `0.53.1+build.4`。
   修复：判重条件由"标签名是否已存在"改为"**该提交是否已有任意标签指向**"，
   这样增量补标只针对真正未打标的提交。

修复后 dry-run 与实际打标结果一致：8 个未打标提交全部覆盖，无重复、无遗漏。

## 说明

- 本轮 8 个提交全部是 `docs`/`chore` 类，按既定策略**不推进版本号**，只用构建元数据（`+build.N`）保证

  构建元数据不影响 SemVer 优先级，仅用于唯一定位提交。
