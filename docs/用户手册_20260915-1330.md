## 第一章　产品简介

### 1.1　一句话理解麒忆智脑
<b>麒忆智脑（MOKOA）= 一套运行在银河麒麟操作系统上的「智能体长期记忆」系统。</b>它给 AI 助手装上记忆：你告诉它的偏好、你上传的文档与经验，都会被它记住，并在你下次对话时自动调用，让回答更贴合你本人。你通过网页与它交互——左边和助手对话，右边实时查看它「记住了什么」，全程无需编程。

### 1.2　为什么需要它
普通 AI 助手每次对话都是「失忆」的：上一轮你说「用中文、给可运行代码」，下一轮它又忘了。麒忆智脑把「记忆」作为独立能力抽出来：
| 没有记忆的助手 | 有麒忆智脑的助手 |
| --- | --- |
| 每次都重复说明偏好 | 偏好一次说完，长期生效 |
| 上传的资料用过即丢 | 资料沉淀为知识，随时被召回引用 |
| 敏感信息可能原样入库 | 手机号/密钥等写入即脱敏、加密 |
| 改主意后旧设定仍干扰 | 更新偏好自动留版本，旧版停用可查 |
| 想删某段记忆无从下手 | 用一句话即可精准遗忘、不可恢复 |

### 1.3　它能为你做什么
| 能力 | 你看得见、用得上的表现 |
| --- | --- |
| 记住偏好 | 你说「用中文回答、给可运行代码」，以后默认都这样；同一偏好更新会保留版本历史。 |
| 沉淀知识 | 上传 PDF / Word / 图片，或粘贴一段经验，它会学会并在问答中引用。 |
| 自动召回 | 每轮回答前自动调出相关记忆与偏好，界面显示检索耗时。 |
| 安全遗忘 | 说「忘掉……」即可删除指定记忆，删除后不可恢复。 |
| 隐私保护 | 手机号、邮箱、密钥等敏感信息在写入时自动脱敏打码，原文加密存储。 |
| 多源接入 | 支持文档、工具结果、用户行为、手动配置、对话五种来源统一入库。 |
| 跨场景隔离 | 不同场景的偏好互不污染，全局偏好与场景偏好分开放置。 |

### 1.4　设计理念
项目没有简单堆叠 Mem0 / MemoryOS / Cognee 等开源记忆库，而是<b>自研了一套「记忆编排核心（Memory Orchestrator）」</b>，把多源摄取、偏好捕捉、知识冲突处理、关联检索、短中长期流转、遗忘与脱敏统一编排起来，再参考三个开源项目的长处。

### 1.5　适用人群与场景
| 人群 | 典型场景 |
| --- | --- |
| 办公人员 | 固定邮件/文档风格、常用术语、项目背景记忆 |
| 开发者/运维 | 命令偏好、镜像源、报错经验、工具用法沉淀 |
| 系统操作员 | 「执行前先确认」「用中文」等安全与交互偏好 |
| 测试/验收同学 | 按指南在麒麟真机跑通主链与指标 |
| 演示讲解 | 左对话右记忆双栏，直观展示「边聊边学」 |

### 1.6　先记住几个关键词
| 词 | 通俗解释 |
| --- | --- |
| 记忆 | 系统为你保存的一切内容，分偏好、知识、行为等类型。 |
| 偏好（Preference） | 你对助手提出的固定要求，如语言、风格、工具选择。 |
| 知识（Knowledge） | 你上传或提供的经验、文档内容，供问答引用。 |
| 场景（Scene） | 一次连续任务上下文，如「项目A」「coding」。场景内偏好可隔离。 |
| 召回（Recall） | 回答前自动找出与你当前问题相关的记忆。 |
| 短期/中期/长期 | 记忆按热度与重要性在三层间流转，越长期越「沉淀」。 |
> **备注**：看不懂这些词没关系，第五~八章会结合界面逐个演示；术语表（第十五章）也可随时回查。

### 1.7　隐私与数据自主权
麒忆智脑把「隐私」当作一等公民，而非事后补丁。三条原则贯穿设计：
| 原则 | 系统落地 |
| --- | --- |
| 数据不出端 | 敏感识别与脱敏在<b>本地</b>完成，不依赖第三方云服务做隐私判断 |
| 原文不落库 | 手机号/邮箱/密钥等写入即替换为加盐哈希占位符（如 `<HASH_7f3a9b>`），敏感原文加密存储 |
| 遗忘可精准 | 一句话即可按类型/关键词/时间范围精准删除，且多库级联、不可恢复 |
> **备注**：脱敏不覆盖所有隐式隐私（如「我住在 XX 小区」这类未命中正则的表述）。涉及高度敏感信息仍建议自行避免输入。

### 1.8　它和「通用记忆库 / 无记忆助手」的差异
| 对比对象 | 麒忆智脑的做法 |
| --- | --- |
| 无记忆的对话助手 | 把「记忆」抽成独立能力：偏好一次说完长期生效、上传资料沉淀为知识随时召回 |
| 直接堆叠 Mem0/MemoryOS/Cognee | 自研编排核心统一调度，仅借鉴三者设计思路，避免功能重叠与答辩成本 |
| 黑盒记忆产品 | 每次入库/拒绝都返回可解释的<b>质量评分与原因</b>（quality_components / reasons），可调可查 |

### 1.9　能力边界与诚实声明
为避免误用，明确以下边界：
- 语义级敏感识别（LLM）代码已就绪，但**默认关闭**，按需通过 `security.semantic_detection.enabled` 开启；未开启时回退正则脱敏。
- 麒麟 SDK 端侧向量性能<b>在真机验收前不宣称已达标</b>；开发机已接入 BGE-M3 本地模型跑通主链。
- 偏好抽取支持「规则 / LLM / 融合」三模式；融合模式在 LLM 不可用时自动降级规则，保证离线可复现。
- 进程内存后端（`memory`）的延迟<b>不得</b>作为 ≤500ms 验收数据；验收须用真实向量后端。

## 第二章　系统如何工作（通俗架构速览）

### 2.1　数据是怎么流动的
你的一次输入（一句话、一个文件、一条经验）会经过下面这条流水线，最终变成「可召回的记忆」：
数据流转：采集→清洗→标准化→质量→去重 → 写入（短期→中期→长期） → 召回注入 → 遗忘级联擦除

### 2.2　五个核心环节
| 环节 | 系统在做什么 | 和你有关的部分 |
| --- | --- | --- |
| 采集 | 从对话、上传、表单等多源收集原始内容 | 你说话、传文件、填表单 |
| 清洗/标准化 | 去噪、统一格式、切片 | 上传扫描件建议补一句说明 |
| 质量 | 对内容打分，低价值不入库 | 页面显示质量评分与原因 |
| 理解 | 判断是偏好还是知识，提取键与值 | 偏好自动成卡片并版本化 |
| 召回 | 按语义+关键词+别名找出相关记忆 | 回答区显示检索耗时与条数 |

### 2.3　记忆的三种形态
系统用三层记忆管理「冷热」：越常被用到、越重要的内容，越往长期沉淀。
| 形态 | 存放内容 | 你看得见的表现 | 流转规则 |
| --- | --- | --- | --- |
| 短期 | 当前会话刚产生的记忆 | 对话中即时出现 | 被多次访问且质量够高 → 升中期 |
| 中期 | 较活跃、经常复用的记忆 | 记忆/偏好页签常驻 | 抽象提炼后 → 升长期/知识库 |
| 长期/知识 | 沉淀的经验与文档 | 跨会话稳定可用 | 最稳定一层，召回优先命中 |
> **备注**：短期记忆默认容量约 10–20 条（热窗口），中期约 50 条，超过会按热度淘汰；中期记忆按「访问次数 + 质量×5 + 置信度」计算热度，低热度被驱逐。这些阈值可在配置中调整（见第十一章）。

### 2.4　一次输入的完整生命周期（时序）
以「在对话里说一句偏好」为例，后台依次发生：
1. **接入**：前端把消息连同 `user_id`、`scene_id` 发给 `/agent/chat`（或 `/ingest`）。
2. **采集 + 信封**：ingestion 校验来源、补齐用户/场景信封、记录 UTC 时间。
3. **清洗**：NFKC 标准化、去 ANSI 控制码、去不可见字符、超长截断。
4. **标准化**：转成统一 `NormalizedRecord` JSON（type / content / time / confidence / source …）。
5. **质量评分**：六维加权打分，低于阈值返回 `low_quality` 拒绝（带原因）。
6. **去重**：质量门控通过后才登记 SHA-256 指纹，TTL 窗口内重复合并。
7. **脱敏**：写入前调用 `filter_sensitive()`，敏感信息替换为占位符并加密索引。
8. **分类**：`classifier` 判断是偏好还是知识，提取键与值。
9. **写入**：进入短期记忆；命中冲突则 `conflict_resolver` 裁决（见 9.4）。
10. **晋升**：被多次访问 / 质量够高时，短期→中期→长期逐级沉淀。
11. **召回注入**：下一轮回答前 `recall()` 按语义 + 关键词 + 别名找出相关记忆，注入 Agent。

### 2.5　核心组件职责一览
| 组件（源码） | 职责 |
| --- | --- |
| `core/orchestrator.py` | 总调度：process_input / classify / consolidate / recall / forget |
| `core/classifier.py` | 偏好 vs 知识分类 |
| `core/conflict_resolver.py` | 新旧记忆撞车裁决（知识取最新事实；偏好看信任 + 时间） |
| `core/recall_ranker.py` | 关联检索排序（语义 / 词面 / 别名 / 项目别名融合） |
| `core/layer_manager.py` + `short_term/mid_term` | 短 / 中 / 长期三层管理与晋升 |
| `core/context_perception.py` | 上下文压缩，窗口达 70–80% 主动重构，用户无感 |
| `ingestion/*` | 多源采集 → 清洗 → 标准化 → 质量 → 去重 |
| `preference/*` | 偏好抽取、版本化、置信度、结构化画像 |
| `security/*` | 脱敏、NL 遗忘解析、索引 AES 加密 |
| `embedding/*` | 统一向量接口（kylin / local / hash） |
| `knowledge/memory_service/*` | 向量存储与检索（Milvus / 麒麟向量） |

### 2.6　记忆分层与流转参数
默认参数（均可在 `configs/default.yaml` 调整，详见第十一章）：
| 参数 | 默认 | 含义 |
| --- | --- | --- |
| 短期容量 | 10 条 | 热窗口；超出按热度淘汰 |
| 中期容量 | 50 条 | 活跃复用记忆上限 |
| 晋升热度阈值 | 3.0 | 短期→中期所需累计热度 |
| 入库质量阈值 | 0.46 | 低于此值不写记忆 |
| 中期相似度门槛 | 0.7 | 中期去重 / 归并语义相似度 |
| 中期抽象提炼(LLM) | false | 是否用大模型做中→长抽象 |

## 第三章　安装与环境准备

### 3.1　环境要求
| 项目 | 本机演示推荐 | 麒麟真机验收 |
| --- | --- | --- |
| 操作系统 | Windows 10/11、macOS 12+、Linux | 银河麒麟桌面 V11（2603+） |
| Python | 3.12（虚拟环境 .venv） | 系统 Python 3.11/3.12 |
| Node.js | 18+（仅前端） | 18+ |
| 内存 | ≥ 8 GB（本地嵌入模型占用较高） | ≥ 8 GB |
| 磁盘 | ≥ 4 GB（含可选 BGE-M3 模型） | ≥ 4 GB |
| 联网 | 首次安装依赖需联网 | 验收阶段按需联网 |
> **提示**：本机快速演示可用「hash 嵌入 + 内存存储」模式，<b>无需大模型、无需 GPU</b> 即可跑通主链路；正式验收再切换为麒麟向量引擎与麒麟 SDK。

### 3.2　方式一：本机快速演示（Windows / macOS / Linux）

#### 步骤 1　准备 Python 环境
```
cd MOKOA
python -m venv .venv
# Windows 激活：
.venv\Scripts\activate
# macOS / Linux 激活：
source .venv/bin/activate
python -m pip install --upgrade pip
```

#### 步骤 2　安装依赖
```
python -m pip install -r requirements.txt
```

#### 步骤 3　（可选）配置对话模型
若想让助手真正「理解并回答」，在 `.env` 填入对话模型密钥；仅演示记忆链路可跳过，此时用规则模式跑通，不调用大模型。
```
# .env
AGENT_API_KEY=sk-xxxx
AGENT_MODEL=deepseek-ai/DeepSeek-V4-Flash
```

#### 步骤 4　启动后端（记忆服务）
```
export OS_AGENT_EMBEDDING_BACKEND=hash   # 演示：无需 GPU
python -m uvicorn api.server:app --host 127.0.0.1 --port 18080
```
后端默认监听 <b>18080</b> 端口。看到 `Uvicorn running on http://127.0.0.1:18080` 即启动成功。

#### 步骤 5　启动前端（网页界面）
```
cd frontend
npm install
npm run dev
```
浏览器访问 <b>http://localhost:5173</b> 即可看到对话界面（前端默认代理指向 18080）。
> **备注**：Windows 上若 `python` 未绑定，可用 `py` 或 `.venv\Scripts\python`；PowerShell 里 `export` 改为 `$env:OS_AGENT_EMBEDDING_BACKEND="hash"`。

### 3.3　方式二：银河麒麟 V11 真机部署（验收）
真机部署遵循「不破坏 OSTree 不可变系统」原则，分六个阶段逐步验证，前阶段未过不跳后阶段：
| 阶段 | 目标 | 通过标志 |
| --- | --- | --- |
| A 系统基线 | 记录系统/CPU/内存/OS 版本 | 留存 baseline 文本与截图 |
| B 主链跑通 | Python+FastAPI+记忆主链可运行 | smoke_e2e 输出 passed:true |
| C 严格 Kylin 嵌入 | 真实 SDK 返回向量，不用 fallback 冒充 | using_fallback=false，得到真实维度 |
| D 接向量库 | 获得真实维度后连 Milvus/麒麟向量引擎 | 集合 schema 与维度匹配 |
| E 前后端全链 | 页面真实读写记忆 | 右栏显示实时数据 |
| F 指标报告 | 标准数据集跑分 | 召回/延迟/冲突/偏好达标 |
> **注意**：⚠️ 严禁为安装开发包擅自解除 OSTree 保护或破坏系统基线；`using_fallback=true` 时不得记为 SDK 通过；进程内存后端的延迟不得作为 500ms 验收数据。详细命令见仓库《测试同学_银河麒麟V11虚拟机部署与验收指南.md》。

### 3.4　方式三：Docker（可选）
仓库提供容器化入口时，可用镜像一键起后端。需在镜像内把 18080 端口映射出来，并把 `.env` 挂载进容器。前端仍可用宿主 `npm run dev` 或构建静态产物。

### 3.5　验证安装
```
curl -i http://127.0.0.1:18080/health
# 期望 HTTP 200 与 {"status":"ok", ...}
```
健康检查通过，说明后端服务、配置、存储后端均已就绪，可以打开前端连接使用了。

### 3.6　配置文件 `.env` 详解
后端敏感项与可切换项都通过 `.env`（或同名环境变量）注入，不写进 YAML。常用项：
| 变量 | 作用 | 示例 |
| --- | --- | --- |
| AGENT_API_KEY / AGENT_MODEL | 对话模型密钥与模型名 | sk-xxx / deepseek-ai/DeepSeek-V4-Flash |
| AGENT_BASE_URL | 对话模型服务基址 | https://api.siliconflow.cn/v1 |
| OS_AGENT_EMBEDDING_BACKEND | 向量后端（hash / local / kylin） | hash（演示免 GPU） |
| OS_AGENT_MEMORY_BACKEND | 记忆存储后端（memory / milvus / kylin） | memory（演示） |
| OS_AGENT_KYLIN_ACCEPTANCE | 验收严格模式开关 | 1（真机验收） |
| MOKOA_SECURITY_KEY | 敏感索引加密密钥（AES-256） | 任意口令，SHA256 派生 |
| SILICONFLOW_API_KEY | 偏好抽取 LLM 密钥 | sk-xxx |
> **注意**：密钥类字段只走环境变量；正文里出现 `sk-xxxx` 仅为占位示意，请替换为真实值。`.env.example` 列出全部可选项。

### 3.7　目录与数据准备
首次启动会在项目根自动创建以下目录（无需手动建）：
| 目录 | 用途 |
| --- | --- |
| `./data/ingestion_staging.db` | SQLite 中转库（审计 + 去重），自动建表 |
| `./data/preferences/` | 偏好版本索引（本地 JSON） |
| `~/.mokoa/security.key` | 敏感索引加密密钥文件（首次自动生成；Windows 不限制权限） |
> **提示**：若要彻底重置本地记忆，停止服务后删除 `./data/` 与 `~/.mokoa/security.key` 再重启即可（注意：该操作会清除已存记忆，不可恢复）。

### 3.8　重装与清理
- **重装依赖**：`python -m pip install -r requirements.txt --upgrade`。
- **重置记忆库**：删除 `./data/` 目录（见 3.7）。
- **重置密钥**：删除 `~/.mokoa/security.key`；下次启动会用新密钥（旧加密索引将无法还原，自动降级为空串）。
- **前端重装**：`cd frontend && rm -rf node_modules && npm install`。

## 第四章　第一次使用（快速开始）

### 4.1　三步走通
以本机演示为例，先后启动「后端」与「前端」两个程序，再用浏览器打开页面：
| 步骤 | 动作 | 预期 |
| --- | --- | --- |
| 1 启动后端 | `uvicorn api.server:app --port 18080` | 终端显示 running on 18080 |
| 2 启动前端 | `cd frontend && npm run dev` | 浏览器可开 5173 |
| 3 连接对话 | 打开页面 → 点连接 → 输入一句话 | 右栏出现真实记忆数据 |

### 4.2　打开页面并连接
1. 打开 `http://localhost:5173` 后，右上角连接按钮显示「演示数据模式」。点击该按钮（或先填好用户 ID 再点「↻ 同步」）连上本地后端。
2. 连接成功后按钮变为「实时 API 已连接」（高亮），右栏状态变为「实时同步」，面板开始出现真实数据。
3. 在左下输入框输入一句话，例如「以后请用中文回答，并优先给出可执行的步骤」，回车或点「发送 ↑」。
> **注意**：⚠️ 未连接后端时页面为「演示数据模式」，仅展示示例数据，不会真正写入记忆。要让记忆真实生效，务必先点连接。

### 4.3　第一次体验「记忆」
建议这样验证记忆真的在工作：
```
① 输入：「以后用中文回答，代码默认 Python，并加注释。」→ 保存本轮内容（默认开）
② 点「新对话」清空会话
③ 再问：「帮我写个读取文件的函数」
④ 开启「使用记忆」时，回答会自动用中文+Python+注释；关闭则不会。
```
> **提示**：对比最直观：同一问题，开/关「使用记忆」开关，观察回答差异。

### 4.4　接入对话模型（让助手真能回答）
仅演示记忆链路可跳过模型；要让助手真正理解并回答，在 `.env` 填：
```
AGENT_API_KEY=sk-xxxx
AGENT_MODEL=deepseek-ai/DeepSeek-V4-Flash
AGENT_BASE_URL=https://api.siliconflow.cn/v1   # 可选，留空用供应商默认
```
填好后重启后端，连接前端即可对话。未填时系统走「规则模式」：仍能写入 / 召回记忆，但不调用大模型生成回答。

### 4.5　三步验证记忆真的生效
1. 连接后端后，左栏说「以后用中文回答，代码默认 Python 并加注释」→ 右栏「偏好」页签应即时出现 `response_language` / `programming_style` 卡片。
2. 点「新对话」清空会话，再问「写个读文件的函数」。开启「使用记忆」时，回答应为中文 + Python + 注释；关闭则不会。
3. 点「＋ 多源接入」上传一个 `.docx` →「上传并写入记忆」；右栏「总览」知识数增加，之后相关提问能在「记忆」页签召回该文档内容。
> **说明**：若偏好页签不出现卡片，先确认「保存本轮内容」开关已开，且已填 `AGENT_API_KEY`（模型用于抽取偏好）。

### 4.6　首跑常见卡点
| 卡点 | 原因 | 处理 |
| --- | --- | --- |
| 后端起不来 | 依赖未装 / 端口占用 | `pip install -r requirements.txt`；换端口或释放 18080 |
| 页面「演示数据模式」 | 未点连接 | 点右上角连接按钮，或填用户 ID 后点「↻ 同步」 |
| 偏好不入库 | 模型未配或开关未开 | 填 AGENT_API_KEY；确认「保存本轮内容」开 |
| 嵌入很慢 | 本地 BGE-M3 模型大 | 演示设 `OS_AGENT_EMBEDDING_BACKEND=hash` |

## 第九章　核心功能怎么用（结合界面）

### 9.1　偏好记忆：让助手记住你的习惯

#### 怎么操作（三种入口）
| 入口 | 做法 |
| --- | --- |
| 对话输入 | 在左栏输入框说偏好，保存本轮内容开启 → 右栏「偏好」页签即时出现卡片 |
| 手动配置 | 接入页签选「手动配置」，填 配置键/值/作用范围 |
| 快捷提问 | 点「新增回答偏好」一键填入示例后发送 |
同一偏好被更新（如「代码改用 Go」）时，右栏偏好页签生成新版本 v2，旧 v1 在版本历史标注「已被替换」。动态键兜底保证长尾偏好不被静默丢弃（落为 habit.custom_*）。

### 9.2　知识沉淀：把资料变成可调用的记忆
用第八章的「多源接入」面板提交。后台经五段式处理（采集→清洗→标准化→质量→去重），质量达标才入库；处理记录区显示质量评分与原因。

### 9.3　自动召回：它怎么「想起来」
「使用记忆」开启时，每轮回答前自动检索。观察点：回答区下方、右栏「记忆」页签（含检索耗时与召回卡片）。召回综合语义相似、关键词/别名、意图识别三类信号。

#### 9.3.1　检索模式 retrieval_mode
API `/recall`（及前端调用）支持三种模式，由 `retrieval_mode` 控制：
| 模式 | 行为 | 何时用 |
| --- | --- | --- |
| auto（默认） | 中英文智能选路：英文开放域问句直接走<b>语义排序</b>（跳过词面全表扫描，P95≈386ms）；命中已知项目别名 / 办公短语的英文放行混合召回 | 日常对话，兼顾速度与覆盖 |
| semantic | 强制语义排序，不做词面补召 | 纯语义意图、中英皆可 |
| hybrid | 语义 + 词面补召双路融合 | 项目别名/专名未进向量候选时保召回 |
> **说明**：auto 模式下英文查询默认走语义路径，正是修复「词面全表扫描导致 P95 破 500ms」的关键；词面补召仅对确实命中已知项目的英文放行，避免再拖慢。

### 9.4　冲突自动消解
| 冲突 | 裁决 | 界面表现 |
| --- | --- | --- |
| 知识冲突 | 知识取最新事实 | 旧值被取代，偏好页签不再显示 |
| 偏好冲突 | 来源信任 + 时间近因 | 更新的、更高信任的胜出，旧版进版本历史 |
| 场景隔离 | 不同场景互不覆盖 | 切场景后对应偏好生效 |

#### 9.4.1　知识冲突：取最新事实
知识类记忆以「事实」为准，不盲信高信任旧来源。规则（见 `conflict_resolver.resolve_knowledge`）：
- 新事实<b>更新鲜</b> → 默认 `REPLACE`（以最新为准）；
- 新事实<b>不更新鲜</b> → `KEEP_OLD`；
- 仅当<b>低信任观测</b>（behavior / tool_result）试图覆盖<b>更高信任旧事实</b>（conversation / manual_config）时，才保留旧值。
> **示例**：手动配置「端口 8080」，之后对话给出更新鲜的「端口 9090」→ 取 9090。这正是修复「手动配置永远压过对话」后冲突正确率达 100% 的关键。

#### 9.4.2　偏好冲突：信任分 + 近因
各类来源有固定信任分（见 `conflict_resolver`）：
| 来源 | 信任分 |
| --- | --- |
| manual_config（手动配置） | 3 |
| conversation（对话） | 2 |
| behavior / tool_result（行为 / 工具结果） | 1 |
裁决逻辑：新来源信任分更高 → 胜出；信任分相同且新事实更新鲜 → 胜出（REPLACE）；否则保留旧版（KEEP_OLD）。同一偏好的旧版本进「版本历史」，可追溯。

### 9.5　短中长期流转
记忆按热度在三层间流动（见 2.3）。右栏「总览」的分层进度条实时反映分布；服务重启后记忆可恢复。

### 9.6　安全遗忘
两种入口：对话内以「忘掉/忘记/删除/清除」开头直接触发；或右栏「遗忘」页签填自然语言点「执行遗忘」。删除不可逆（见 7.6）。记忆卡片与偏好卡片上的「准备遗忘」按钮可一键把目标填入遗忘页签。

### 9.7　隐私保护
写入时手机号/邮箱/密钥等约 58 条正则脱敏、AES 加密；遗忘页签的隐私提示明确「前端不会伪造成功结果」。涉及高度敏感信息请自行避免输入。

### 9.8　偏好抽取三模式与降级
偏好抽取支持三种运行模式（由 `preference.*` 配置，详见 11.14）：
| 模式 | 配置 | 行为 |
| --- | --- | --- |
| 规则 | use_llm=false, allow_rules=true | 只走规则抽取，离线可复现 |
| LLM | use_llm=true, allow_rules=false | 只走大模型；失败则空结果（无规则兜底） |
| 融合（默认） | use_llm=true, allow_rules=true | 先 LLM；无密钥 / 超时 / 空结果时自动降级规则；规则补漏长尾 |
> **提示**：默认「融合」模式最稳——联网时用大模型抓长尾表达，断网或超时自动回规则，不漏掉明确偏好。实测精确率 100% / 召回率 95.83%（规则模式，35 条金标准）。

### 9.9　动态键兜底（长尾偏好不丢）
当一条偏好无法归入已有标准键（如 `response_language`、`programming_style`）时，系统不会静默丢弃，而是自动归类到 `habit.custom_*` 命名空间（例如 `habit.custom_coding_language`）；类别也不合法时兜底到 `habit.custom_{话题}`。这样任意长尾习惯都能被记住、被召回、可被遗忘指令命中。
> **说明**：标准偏好类别共 6 类：`habit`（习惯）、`style`（风格）、`security`（安全策略）、`tool_selection`（工具选择）、`workflow`（工作流）、`communication`（沟通）。`habit` 之外的新类别也走 `habit.custom_*`。

## 第十一章　配置参考（完整版）

本章逐条说明项目**唯一**的配置文件 `configs/default.yaml` 中每一个可配置项：它的**配置路径**（YAML 中的点分键）、**默认值**、可被哪个**环境变量**覆盖、有哪些**可选值**，以及每一项**含义与对系统行为的影响**。所有默认值均逐字对照源码 `configs/default.yaml` 与加载器 `src/common/config.py`。

### 11.0　配置从哪读取、优先级如何

- **唯一配置文件**：`configs/default.yaml`（仓库 `configs/` 目录下）。
- **加载器**：`src/common/config.py` 启动时读取该 YAML，对外提供 `CONFIG.get(path, default)`、`get_int`、`get_float`、`get_bool`。上层业务一律通过 `CONFIG.get("a.b.c")` 取配置，不直接读文件。
- **三层优先级（高 → 低）**：① 环境变量（最高，且只有环境变量能覆盖密钥类字段） ② `default.yaml` 中的值 ③ 代码内置兜底默认值。
- **密钥原则**：API Key、令牌等敏感字段**只允许通过环境变量注入**，绝不写在 YAML 里。

### 11.18　`auto` 的自动解析规则
`memory_backend` 与 `embedding.backend` 设为 `auto` 时，运行期按以下规则选择真实后端：

- **storage.memory_backend = auto**：
  1. 若处于测试（`pytest`）环境 → `memory`（进程内，不落盘）；
  2. 若在银河麒麟 V11 用户态且可加载向量 SDK（`vector_library` 已配置）→ `kylin`；
  3. 否则 → `memory`。
  > **注意**：显式填写 `memory` / `milvus` / `kylin` 时直接使用；填非上述值会报错。验收阶段须拿到真实向量维度，严禁用 `memory` 后端延迟冒充 500ms 指标。
- **embedding.backend = auto**：按运行环境在 `kylin` / `local` / `hash` 间择优；演示无 GPU 时可显式设 `hash` 免模型依赖。

### 11.19　推荐配置组合
| 场景 | 关键配置 |
| --- | --- |
| 本机快速演示 | `OS_AGENT_EMBEDDING_BACKEND=hash` + `OS_AGENT_MEMORY_BACKEND=memory`，对话模型填 `AGENT_API_KEY/AGENT_MODEL`（或不填走规则模式） |
| 银河麒麟真机验收 | `OS_AGENT_KYLIN_ACCEPTANCE=1`，配齐 `kylin.vector_library/vector_endpoint`，`embedding.backend=kylin`，`storage.memory_backend=kylin`，`staging_raw_archive_mode=redacted` |

> **说明**：本机演示最小配置：只设 `AGENT_API_KEY/AGENT_MODEL` + `OS_AGENT_EMBEDDING_BACKEND=hash` + `OS_AGENT_MEMORY_BACKEND=memory` 即可跑通主链路。正式验收须切换为麒麟向量引擎与麒麟 SDK（`OS_AGENT_KYLIN_ACCEPTANCE=1`），且 `kylin.strict=true` 下禁用 fallback 冒充。


## 第十二章　命令与接口参考

后端基于 FastAPI（`api/server.py`），所有接口以 JSON 通信，默认监听 `18080`。本章给出面向使用 / 联调最常用、最核心的端点与字段；完整 OpenAPI 文档见服务启动后的 `/docs`。

### 12.1　常用命令

### 12.3　/agent/chat 请求与返回（节选）
前端发送：`user_id`、`message`、`history`（最近 20 轮）、`use_memory`、`save_memory`。返回含 `answer`、`memories`（本轮召回）、`recall_ms`（检索耗时）、`latency_ms`（总耗时）、`memory_write.status`（accepted / rejected / disabled / failed / skipped）、遗忘时含 `deleted_ids`、`reset_history`。
> **备注**：消息以「忘掉/忘记/删除/清除」开头会在对话内直接触发遗忘，不调用模型生成，并清空当前会话。

### 12.4　/ingest（多源写入）请求与返回
请求体 `IngestRequest`：
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| user_id | string | 用户标识（必填；缺失时空兼容为 `default`） |
| source | string | 来源：tool_result / user_behavior / manual_config / conversation / document |
| payload | object | 来源专属内容（如 `action`/`target`/`content`/`key`/`value`） |
| scene_id | string? | 场景隔离键；留空 = 全局 |
返回体含：`accepted`、`memory_id`、`memory_type`、`status`(accepted/rejected)、`reject_code`、`reasons`、`quality_score`、`fingerprint`、`processing_ms`、`stage_ms`、偏好相关 `preference_extracted` / `preference_keys` / `preference_stored_ids`。
> **说明**：`/ingest/file` 为 `multipart/form-data`，额外带 `caption`（内容说明）；单文件 ≤50MB，其余限制见 12.5 中间件。

### 12.5　/preferences/extract（偏好抽取）请求
请求体 `PreferenceExtractRequest`：`user_id`、`text`、`scene_id?`、`source`(默认 conversation)。返回 `extracted_count`、`mode`(rule/llm)、`degraded_to_rules`、`entries`（抽取结果）、`stored`（实际入库项含 memory_id / superseded_memory_id）。
> **提示**：前端「新增回答偏好」本质就是调这个接口；抽取走 9.8 的融合模式，断网自动降级规则。

### 12.6　/recall（检索）请求与返回
请求体 `RecallRequest`：
| 字段 | 类型 | 默认 / 范围 | 说明 |
| --- | --- | --- | --- |
| user_id | string | 必填 | 用户标识 |
| query | string | "" | 检索问句；空串返回近期记忆 |
| top_k | int | 5（1–100） | 返回条数上限 |
| memory_type | enum? | null | 仅查 preference / knowledge |
| scene_id | string? | null | 场景过滤 |
| filters | object | {} | 额外过滤条件 |
| retrieval_mode | string | auto | auto / semantic / hybrid（见 9.3.1） |
返回：`count`、`latency_ms`、`strategy`(如 `query_memory:auto-semantic`)、`items`（记忆卡片列表）。

### 12.7　/forget（自然语言遗忘）请求与返回
请求体 `ForgetRequest`：`user_id`、`instruction`（自然语言，如「忘掉关于镜像的偏好」）。返回：`count`（实际删除数）、`deleted_ids`（真实 memory_id 列表）。后端会按占位符 / 关键词 / 类型解析目标，级联擦除短期 / 中期 / 长期 / 向量库 / 中转库，并同步清理偏好版本索引（见第十三章）。
> **注意**：全量删除需指令显式包含「所有」且限定类型才放行；普通删除有 `min_score=0.6` 置信度门控防误删。

### 12.8　安全加固（中间件）
| 机制 | 默认 | 说明 |
| --- | --- | --- |
| 可选鉴权 | 关（配 `API_AUTH_TOKEN` 后开） | 除 `/health` 外均需 `Authorization: Bearer <token>`，否则 401 |
| CORS | 本地前端 | `API_CORS_ORIGINS` 限定来源；未配置仅放行本地且不带凭证（绝不 `*`+credentials） |
| 限流 | 120 次 / 60 秒 / IP | 滑动窗口超阈值返回 429 |
| 请求体上限 | JSON 8MB / 文件 50MB | 超 413 |
| 处理超时 | 180 秒（流式除外） | 超 504 |
| 统一错误 | — | 业务异常不泄露内部细节；未捕获异常返回通用 500 |

### 12.9　/health 返回差异
- 常规：`{"status":"ok","memory_backend":...,"embedding_backend":...}`。
- 验收严格模式（kylin）：额外返回 `kylin_strict`、`using_fallback`、`vector_dim`、`vector_sdk`、`collection`、`pid`、`run_id`，且要求 `using_fallback=false`、真实 SDK 与真实向量维度匹配。
> **注意**：`using_fallback=true` 时<b>不得</b>记为 SDK 通过；进程内存后端延迟<b>不得</b>作为 ≤500ms 验收数据。

## 第十三章　隐私与数据安全
隐私是这套系统的设计重点，而非附加项（对应赛题要求 (5)）。本章把「你关心的」逐项讲清机制与边界。

### 13.1　你要关心的五件事
| 你关心的 | 系统怎么做 |
| --- | --- |
| 我的手机号/邮箱会不会入库 | 写入即脱敏为占位符，原文不落库 |
| 敏感原文存哪 | AES 加密存储，密钥来自环境变量或本地密钥文件 |
| 删了还能找回吗 | 不能。遗忘在多库级联擦除，不可恢复 |
| 它会不会把我的隐私泄露给模型 | 占位符与类型保留明文用于检索，敏感原文不进模型上下文 |
| 我有高度敏感信息怎么办 | 脱敏不覆盖所有隐式隐私，请自行避免输入 |

### 13.2　脱敏覆盖的敏感类型
脱敏由 `security/service.py` 中<b>约 58 条正则</b>实现，覆盖 52+ 类敏感信息（满足赛题「敏感识别过滤」）。典型类别：
| 类别 | 示例 |
| --- | --- |
| 身份与证件 | 身份证、外国人永居证、护照、印度 Aadhaar、统一社会信用代码、出生日期 |
| 通讯 | 手机号（含 +86/带分隔符）、固定电话、邮箱、验证码/OTP |
| 金融 | 银行卡（16–19 位，含有效期）、加密货币钱包（BTC/ETH/TRX）、 |
| 网络与设备 | IPv4、MAC 地址、车牌号、SSH 私钥、设备标识 |
| 凭证与密钥 | 密码/口令（含 Wi-Fi）、API Key、Access/Bearer/JWT/Bot Token、Git 仓库 URL（含密码）、数据库连接串（含密码）、Tor Onion 地址 |
> **说明**：识别后替换为<b>不可逆加盐哈希占位符</b>（如 `<HASH_7f3a9b>`），并建立「占位符↔原文」的本地索引；仅靠占位符无法还原，还原依赖本地索引文件，实现隐私与记忆分离。

### 13.3　索引加密（AES-GCM）
敏感原文的「占位符↔原文」映射由 `SensitiveIndex` 持久化，且<b>仅原文加密</b>（`placeholder_id`/`type` 留明文，保证检索与统计性能不受损）：
- **算法**：AES-256-GCM（带认证标签，防篡改）。
- **密钥来源**：环境变量 `MOKOA_SECURITY_KEY` 优先（任意口令经 SHA256 派生 32 字节）；未配置则首次在 `~/.mokoa/security.key` 自动生成（非 Windows 限制 0600 权限）；文件不可写时退化为进程内随机密钥（重启后旧索引无法解密）。
- **密文格式**：`MOKOA1:<base64(nonce)>.<base64(ciphertext+tag)>`，前缀用于区分明文（兼容历史索引）与版本识别。
- **降级**：密钥变更 / 数据损坏导致解密失败时返回空串，不抛异常中断加载。

### 13.4　自然语言精准遗忘
遗忘由 `security/forget_parser.py` + `Orchestrator.forget` 实现：
- **解析**：把「忘掉关于我手机号的记忆」这类指令拆成<b>类型意图</b>（手机号→`phone`）+ <b>话题词</b>，两级打分（候选词元反向命中指令为核心）。
- **防误删**：置信度门控 `min_score=0.6`；<b>全量删除</b>需指令显式含「所有」且限定类型才放行。
- **标准键**：解析结果携带 `preference_key`（如 `habit.download_path`），便于前端展示与审计。
- **级联擦除**：按占位符软删敏感索引，按 memory_id 级联删除短期 / 中期 / 长期待入库 / Milvus / 中转库，并同步清理本地偏好版本索引（见 9.6、7.6）。
> **提示**：普通记忆/偏好的精准遗忘也已打通——非敏感内容（如下载路径偏好）同样能被一条自然语言指令命中删除。

### 13.5　上下文维护（无感压缩）
对应「上下文会越攒越长」问题，由 `core/context_perception.py` 在上下文达窗口 70–80% 时<b>主动</b>重构：
- **永不压缩**：系统提示词 / 用户提示词 / 长期记忆（偏好、系统指令、角色设定）。
- **保持不变**：最近几轮对话（当前意图核心）。
- **压缩为摘要**：中间工具调用（「已执行 3 个命令…」）、早期重复/已解决对话（「曾咨询 Python 虚拟环境，已推荐 conda」）。
- **三层策略**：关键词快速过滤 → 模型摘要 → 语义检索兜底；按 Token 压力 / 语义活跃度 / 信息密度动态选择。对用户全程无感。

### 13.6　中转库与保留期
ingestion 在脱敏之前写入 SQLite 中转库做审计与去重（非最终记忆库）。敏感处理：
- 原始报文默认 `redacted`（递归脱敏后归档）；`off` 不写 raw 行；`plaintext` 仅供 dev 且需双确认。
- 手动 / 自动清理默认 **7 天 raw / 90 天 audit**（自动间隔 `staging_auto_purge_interval_seconds`，默认 1h）。
- `/forget` 命中本地或 Milvus ID 后同步擦除 staging content、删除 raw 与 TTL 指纹。

### 13.7　多用户隔离
全链路按 `user_id` 隔离：不同用户的记忆、偏好、脱敏索引、中转库互不可见（验收用例「用户 A 遗忘不删用户 B」通过）。生产 API 必须注入真实用户标识，否则无法实现可靠隔离与精准遗忘。

### 13.8　P0 验收六条（自然语言遗忘）

| --- | --- | --- |

## 第十四章　故障排查与常见问题

### 14.1　现象 → 原因 → 处理
| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 右栏一直「演示模式」、无真实数据 | 未连接后端 | 点连接按钮；确认后端已在 18080 启动、/health 正常 |
| 前端连不上后端 | 端口/代理失配 | 后端监听 18080；或改前端代理目标为实际端口 |
| 偏好不入库 | 保存本轮内容未开，或模型未配置 | 确认开关开启；检查 AGENT_API_KEY 是否填入 |
| 觉得「检索很慢」 | 误看总耗时 | 以右栏「记忆」页签的检索耗时(ms)为准，总耗时含模型生成 |
| 遗忘后好像还在 | 看的是旧会话缓存 | 遗忘会清空当前会话；重新查询记忆确认已删除 |
| 上传文件无反应 | 超 8MB 或类型不符 | 单文件≤8MB，支持 PDF/Word/常见图片；点「上传并写入记忆」才发送 |
| 处理记录显示「未接收」 | 质量门控或重复 | 看原因代码，补充更有信息量的内容再投 |
| 本地嵌入很慢/占内存 | BGE-M3 本地模型较大 | 演示用 hash 后端；或加内存/换 kylin 后端 |
| 麒麟上 SDK 返回 fallback | 未拿到真实维度 | 检查 OS_AGENT_KYLIN_ACCEPTANCE 与库路径，严禁用 fallback 冒充 |
| 对话无回答 | 模型密钥/地址错误 | 核对 AGENT_API_KEY/AGENT_MODEL/AGENT_API_BASE |
| 页面打不开 5173 | 前端未启动或端口被占 | npm run dev 重试；或换端口 |
| 切换用户数据不变 | 未同步 | 改完用户 ID 按回车或点「↻ 同步」 |
| /ingest 返回 413 | 请求体超 8MB | 拆分 payload；文件走 /ingest/file（上限 50MB） |
| /recall 偶发 504 | 单请求超 180s | 检查模型/向量库是否卡住；流式对话不受影响 |

### 14.2　推荐排查顺序
多数问题集中在「没连后端 / 开关没开 / 端口不对」三点，按此顺序能解决 80%：
1. **点连接**：右栏状态灯变「实时同步」才算连上；演示模式操作不落库。
2. **查 health**：`curl -i http://127.0.0.1:18080/health` 期望 `200` + `{"status":"ok",...}`。
3. **对端口**：后端 `18080`、前端 `5173`；前端代理目标须指向后端实际端口。
4. **查开关**：「保存本轮内容」「使用记忆」是否开启（默认开）。
5. **核密钥**：对话无回答先核 `AGENT_API_KEY/AGENT_MODEL/AGENT_BASE_URL`。

### 14.3　用日志定位
- 后端日志级别由 `logging.level`（默认 INFO）控制；排障可临时调 `DEBUG` 看 ingestion 各阶段耗时（`stage_ms`）、召回策略（`strategy`）、脱敏命中。
- 中转库统计：`GET /staging/stats` 看拒绝码分布（invalid_source / empty_content / low_quality / duplicate …）与处理耗时分位，定位「为什么没入库」。
- 拒绝属于正常业务结果，<b>不会</b>记成 500 错误；只有未捕获异常才返回通用 500（不泄露内部细节）。
