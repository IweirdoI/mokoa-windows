## 2. 新接口：`POST /ingest/file`

解析文件后，走和 `POST /ingest` **同一条** 记忆写入链（清洗 → 质量门 → 短期记忆）。`source` 固定为 `document`，前端不用自己传。

| 项 | 值 |
|---|---|
| URL | `/api/ingest/file`（开发代理后等同后端 `/ingest/file`） |
| Content-Type | **不要自己设**。用 `FormData`，让浏览器带 `multipart/form-data; boundary=...` |
| 超时 | 建议 180s。视觉模型看图或首次加载会慢 |

### 表单字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `file` | 是 | 单个文件。PDF / `.docx` / 常见图片 |
| `user_id` | 是 | 与顶栏用户 ID 相同；空字符串会被拒 |
| `scene_id` | 否 | 建议 `document_upload` |
| `caption` | 否 | 用户对这张图/这份扫描件的一句话说明 |

支持的文件：

- PDF（`.pdf`）
- Word（仅 `.docx`，**不支持旧版 `.doc`**）
- 图片：`.png` `.jpg` `.jpeg` `.webp` `.bmp` `.gif`

上限 **8MB**。超限、空文件、无法识别的类型都会业务拒绝，HTTP 仍是 200。

### 前端必须用原生 `fetch`，不要走现有 `fetchWithTimeout`

`fetchWithTimeout` 会强行加上 `Content-Type: application/json`，multipart 会被拆掉。文件上传请单独写：

```js
const form = new FormData()
form.append('file', file)
form.append('user_id', userId)
form.append('scene_id', 'document_upload')
if (caption) form.append('caption', caption)

const controller = new AbortController()
const timer = window.setTimeout(() => controller.abort(), 180000)
const response = await fetch('/api/ingest/file', {
  method: 'POST',
  body: form,
  signal: controller.signal,
})
window.clearTimeout(timer)
```

`accept` 建议：

```
.pdf,.docx,.png,.jpg,.jpeg,.webp,.bmp,.gif,application/pdf,application/vnd.openxmlformats-officedocument.wordprocessingml.document,image/*
```

## 3. 返回值（和 `/ingest` 对齐，多一个 `filename`）

HTTP **200 不代表写入成功**。以 `accepted` / `status` 为准。

成功示例：

```json
{
  "accepted": true,
  "status": "accepted",
  "user_id": "demo_user",
  "filename": "guide.docx",
  "memory_id": "mem_xxx",
  "memory_type": "knowledge",
  "reject_code": null,
  "reasons": ["质量评分 0.82 通过阈值 0.60"],
  "quality_score": 0.82,
  "fingerprint": "…",
  "updated_existing": false,
  "processing_ms": 42.1,
  "record": {
    "type": "document",
    "content": "用户上传Word「guide.docx」：……",
    "metadata": {
      "filename": "guide.docx",
      "file_kind": "docx",
      "ocr_used": false,
      "vision_used": false
    }
  }
}
```

失败示例（图片没字、没说明、模型也不会看图）：

```json
{
  "accepted": false,
  "status": "rejected",
  "filename": "shot.png",
  "memory_id": null,
  "reject_code": "empty_content",
  "reasons": ["清洗后没有可形成记忆的有效正文"],
  "record": null
}
```

前端要读的字段：

| 字段 | 用法 |
|---|---|
| `accepted` / `status` | 是否写入 |
| `filename` | 聊天气泡、活动流 |
| `memory_id` | 展示记忆编号 |
| `memory_type` | 文档一般是 `knowledge` |
| `reasons` / `reject_code` | 失败时原样展示中文原因 |
| `record.metadata.file_kind` | `pdf` / `docx` / `image` |
| `record.metadata.vision_used` | 是否由视觉模型看图 |
| `record.metadata.ocr_used` | 是否走了本地 OCR |
| `record.metadata.caption` | 用户当时写的说明 |

## 4. 写入成功后要晋升，否则下一轮 `/recall` 看不到

文档和对话知识一样，先落短期。`/recall` 只打向量库。

`accepted === true` 且 `memory_type === 'knowledge'` 时，再调一次：

```
POST /api/consolidate/{user_id}
```

超时同样建议 180s。失败不要当成上传失败，在活动流里提示「知识晋升失败」即可。

然后 `GET /stats/{user_id}`、偏好列表等按你现在的 `loadDashboard` 刷新。

## 5. 三种文件，页面上怎么提示

| 类型 | 后端怎么处理 | 前端建议 |
|---|---|---|
| 可复制文字的 PDF / Word | 本地抽文本，不依赖多模态 | 选文件即可，说明可选 |
| 扫描件 PDF（抽不出字） | 必须靠 `caption` | 提示「扫描件请在输入框写一句内容说明」 |
| 图片 | 当前模型有视觉能力 → 把图交给模型描述；否则 OCR；再没有就用 `caption` | 输入框当说明；无说明且解析失败时展示 `reasons` |

当前默认模型 `qwen3.5-0.8b` **没有视觉**。换成本地 `qwen2.5-vl` / `gpt-4o` 这类名字后，后端会自动看图，前端不用改请求。

旧版 `.doc` 会被拒，文案可以写：「请另存为 .docx」。

## 6. 常见拒绝码

这些都是 **HTTP 200 + `accepted: false`**，不要当成网络错误。

| `reject_code` | 典型原因 | 建议文案 |
|---|---|---|
| `invalid_source` | `.doc`、`.txt` 等不支持 | 仅支持 PDF、Word（.docx）和常见图片 |
| `invalid_payload` | 空文件、超过 8MB、文件损坏 | 展示 `reasons` |
| `invalid_user_id` | `user_id` 为空 | 请先填写用户 ID |
| `empty_content` | 图片/扫描件没抽出字，也没说明 | 请在输入框补充一句说明后再传 |
| `low_quality` | 抽到的字太短、信息量不够 | 展示 `reasons`，可让用户加说明重试 |
| `duplicate` | 同一用户短时间重复传同一份 | 这份文件刚刚已经记过了 |

`user_id` 缺失时后端会落到 `default`（Demo 兼容）。正式演示请始终带上顶栏用户 ID。

## 7. 不要做的事

1. **不要** 先调 `/ingest/file` 再把返回正文拿去调一次 `/ingest`。会写进两条记忆。
2. **不要** 把文件转成 base64 塞进 `/ingest` 的 JSON。文件入口只有 multipart。
3. **不要** 在 JSON 封装函数里发 FormData。
4. **不要** 在演示模式假装解析成功。连不上 API 时明确说「演示模式不会解析文件」。
5. **不要** 改 `src/ingestion/`。缺字段找3fba60e1，缺 HTTP 壳找efca9634。
