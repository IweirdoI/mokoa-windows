# 改动

按这份赛题，**Mem0 只能当底座，不能原样交差**。需要围绕「OS Agent + 麒麟端侧」做一轮定向改造，而不是再造一套通用记忆框架。

***

## 一句话结论

| **维度**     | **判断**                                                     |
| ---------- | ---------------------------------------------------------- |
| Mem0 能直接用的 | 向量存储、抽取、检索、增删改查、历史轨迹                                       |
| 必须补齐/改造的   | 偏好/知识双轨、多源接入、冲突与版本、麒麟 Embedding、端侧轻量、敏感过滤与遗忘、短中长期流转、赛题指标评测 |

***

## 对照赛题：需要做的事

### 1. 多源数据整合（赛题必做，Mem0 几乎没有）

赛题要求：工具执行结果、用户行为、手动配置和对话 → 清洗、标准化、质量校验。

Mem0 现状：主要吃对话 `messages`，不专吃工具结果/OS 行为日志。

需要做的事：

* 增加接入层：`tool_result` / `user_behavior` / `manual_config` / `conversation`（当前已实现）
* 做 schema 标准化、质量过滤（失败调用、噪声、重复）
* 再交给 Mem0 的 `add`，或先落中间表再抽取

### 2. 偏好记忆动态捕捉 + 版本化（核心改造）

赛题要求：操作习惯、输出风格、安全策略；自动提取、版本管理、跨场景复用与回溯。

Mem0 现状：统一「事实记忆」，有 `history`，但**没有偏好类型、版本号、场景维度**。

需要做的事：

* 拆出 `preference` 类型（可 metadata / 独立 collection）
* 版本字段：`version`、`scenario`、`valid_from/to`
* 偏好冲突时「新版本覆盖 + 可回溯」，不是简单覆盖文本
* 跨场景：`scenario` / `app_id` 过滤复用

### 3. 知识记忆结构化 + 冲突融合 + 关联检索（核心改造）

赛题要求：工作流知识、历史案例、可复用模板；新旧冲突、关联检索。

Mem0 现状：语义检索 + 可选图存储；冲突主要靠 LLM 去重更新，**没有知识类型结构、明确冲突策略**。

需要做的事：

* 知识分类：`workflow` / `case` / `template`
* 冲突策略：时间优先、置信度、人工确认等，并能量化「冲突处理正确率 ≥88%」
* 关联检索：实体/标签边 + 向量，不只做纯相似度

### 4. 麒麟端侧适配（硬性适配，必须做）

赛题要求：银河麒麟桌面 **embedding SDK**、轻量存储、检索 **≤500ms**。

Mem0 现状：默认 OpenAI embedding + Qdrant（偏服务端），**无麒麟 SDK**。

需要做的事：

* 按 Mem0 插件模式写 `KylinEmbedding` 提供者
* 换轻量后端：本地 FAISS / 精简 Chroma / 文件型向量，控制内存
* 裁剪链路：少调云端 LLM、批处理、缓存、降维/量化
* 出适配测试报告（赛题明确要求）

### 5. 敏感信息过滤 + 自然语言遗忘（必须加）

赛题要求：敏感识别过滤；自然语言指令精准遗忘。

Mem0 现状：有 `delete`/`delete_all`，**敏感过滤、NL「忘掉 XXX」解析基本没有**。

需要做的事：

* `add` 前脱敏（证件号、路径隐私、口令等）
* 意图解析：「忘掉我的代理设置偏好」→ 定位 preference → 删/失效
* 审计日志（删了什么、何时删）

### 6. 与短/中期记忆流转（架构层要设计）

赛题要求：兼容短期、中期记忆流转。

Mem0 现状：大致有 `run_id`（会话）与 `user_id`（长期），**没有清晰 STM → MTM → LTM 流水线**。

需要做的事：

* 短期：当前会话上下文 / buffer
* 中期：近期任务摘要、近期工具轨迹
* 长期：沉淀后的偏好与知识（进 Mem0）
* 明确晋升/淘汰规则，并在文档里写清交互逻辑

Mem0 已解决：长期记忆引擎怎么抽、怎么存、怎么检。

赛题还要求：偏好/知识双轨、工具结果多源、冲突版本、麒麟 Embedding、敏感遗忘——这些需要在 Mem0 之上或插件层补充，不是 Mem0 原生就有的。

### 7. 量化评测（交付物，不能省）

硬指标：

* 偏好提取准确率 ≥85%
* 知识检索召回率 ≥85%
* 检索延迟 ≤500ms
* 冲突处理正确率 ≥88%

需要做的事：构造/使用赛方数据集，对比基线（原版 Mem0 vs 改造版），出完整测试报告。

## 建议改造优先级

```text
P0 必须做（否则不合格）
├── 麒麟 Embedding SDK 接入 + 端侧轻量存储 + ≤500ms
├── 偏好 / 知识双轨结构 + 版本与冲突
├── 多源接入（尤其工具调用结果）
├── 敏感过滤 + NL 遗忘
└── 评测与麒麟适配报告

P1 强相关（拉开分差）
├── 短/中/长期流转机制
├── 关联检索（实体/图 + 向量）
└── OS Agent 真实场景 demo（办公自动化等）

P2 加分
├── 偏好提取算法创新点（答辩「技术创新性 30 分」）
└── 冲突融合策略创新
```

***

## 对 Mem0 的改造边界（少走弯路）

| **建议**                                             | **原因**                                 |
| -------------------------------------------------- | -------------------------------------- |
| **保留** `Memory` API、factory 插件、向量检索主链路             | 少重复造轮子                                 |
| **扩展** embedding / 向量库 / metadata schema / prompts | 契合赛题且改动可控                              |
| **外挂一层**「OS Agent Memory Orchestrator」             | 多源接入、STM/MTM、偏好版本、冲突策略放这里，别全塞进 Mem0 内核 |
| **不要指望**只改配置就达标                                    | 赛题要的是 OS Agent 记忆方案，不是 Mem0 二次包装       |

***

## 最小可行架构示意

```text
工具结果 / 行为 / 配置
        ↓
  多源清洗标准化
        ↓
  敏感过滤 → 抽取
        ↓
   ┌────┴────┐
偏好记忆(版本化)  知识记忆(结构化+冲突)
   └────┬────┘
        ↓
麒麟 Embedding + 轻量向量库
        ↓
检索复用 ←→ 短/中期记忆升降级
        ↓
自然语言遗忘 / 安全合规
```

***

**总结：** 不是「把 Mem0 改好就能持久记忆」，而是「用 Mem0 当长期记忆引擎，上面补 OS Agent 专属的偏好/知识双轨、多源与冲突、麒麟端侧与评测」。创新分主要打在偏好提取、冲突处理、关联检索这三块，不要只做接入封装。
