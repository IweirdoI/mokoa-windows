# 代码注释充分性审查报告

- 审查日期：2026-09-14
- 审查范围：`src/`、`api/`、`scripts/`、`benchmarks/` 下的 Python 源码（tests 低优先级）
- 审查方式：静态阅读 + 模式扫描，未修改业务逻辑，仅在本次一并修复了脱敏遗漏（见「紧急项」）

## 总体结论

核心模块（`orchestrator`、`pipeline`、`security`、`staging`、`index_crypto`、限流等防御/加密代码）的**模块级/类级 docstring 质量普遍较好**，业务流程分支注释较充分。主要薄弱点集中在两类：

1. **核心算法里的魔法数字 / 阈值 / 权重缺少取值依据**（直接影响记忆是否持久化、检索相关性、压缩策略）。
2. **少量公共方法 / 脚本辅助函数缺 docstring**；另有**上轮脱敏遗漏一处真实姓名**、以及探针脚本硬编码密钥一处安全隐患。

## 🟠 高优先级（核心算法阈值/权重无依据）

1. `src/knowledge/memory_service/memory_policy.py`（~L20, L24-34）
   - `SAVE_THRESHOLD = 0.46` 入库/持久化决策阈值，为裸字面量，无"为什么是 0.46"的说明。
   - `score_save` 中权重增量 `+0.15`（偏好）、`+0.1`（反馈/用户明确）、`-0.5`（隐私风险）、`-0.4`（临时）及 `max(0.0, min(1.0, score))` 无语义注释。
   - 建议：为 `SAVE_THRESHOLD` 补来源注释（经验值/离线校准？），权重抽成具名常量（`_PREF_BONUS` 等）并注明语义。

2. `src/core/recall_ranker.py`（L332, L341 `term_overlap`）
   - `score += 8`（命中主题组）、`score += 3 if len(needle) >= 4 or needle.isascii() else 1`（重叠针）无归一化说明，下游如何解读不清楚。
   - 建议：提为常量并注释"主题命中 vs 词元命中"设计意图，说明该分数为相对量纲。

3. `src/core/recall_ranker.py`（L361 `is_cross_language`）
   - `(q >= 0.4 and c <= 0.1) or (c >= 0.4 and q <= 0.1)` 中 `0.4 / 0.1` 是语种占比切分阈值，无"40% 主导 / 10% 可忽略"的解释。
   - 建议：提为 `_CJK_DOMINANT_RATIO=0.4` / `_OTHER_MINOR_RATIO=0.1` 并注释判定语义。

4. `src/core/context_perception.py`（L207-210 `_select_strategy`）
   - `token_pressure > 0.9` / `> 0.6`、`volatility > 0.7` 三个阈值裸写，`token_pressure` 量纲（0~1 窗口占用率？）未说明。
   - 建议：注释量纲与来源，阈值抽为命名常量。

5. `src/core/mid_term.py`（L103-106 `__init__`）
   - `similarity_threshold=0.7`、`recency_tau_hours=168.0`（=7 天近因衰减）、`keyword_alpha=0.3`、`recency_gamma=1.0` 全为裸字面量。
   - 建议：逐参数补"取值含义/来源"注释，`168.0` 标注"=7 天近因衰减时间常数"。
