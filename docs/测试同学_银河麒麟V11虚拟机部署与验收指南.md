# 测试同学：银河麒麟 V11 虚拟机部署与验收指南

> 项目：麒忆智脑（XA-202612 OS Agent 记忆优化及高效应用研究）
>
> 适用对象：负责功能测试、指标评测、麒麟适配报告和演示证据留存的同学
>
> 更新日期：2026-08-23

## 1. 本文档的目标

本文档用于指导测试同学在银河麒麟 V11 虚拟机中：

1. 不破坏 V11 的 OSTree/不可变系统保护；
2. 先证明项目的 Python、FastAPI 和核心记忆链路可运行；
3. 再严格验证银河麒麟 Embedding SDK，不用 fallback 结果冒充真实 SDK 结果；
4. 获得真实向量维度后再连接 Milvus；
5. 按比赛要求留存环境、命令、原始输出、指标和截图。

本项目的正确部署定位是：

> 原生运行于银河麒麟的 FastAPI 记忆服务，直接调用宿主系统 Embedding SDK；前端与上层 Agent 通过 HTTP API 访问。

## 2. 必须区分的四种状态

| 状态 | 可以证明什么 | 不能证明什么 |
|---|---|---|
| 代码已合并 | 代码已进入 `master` | 在麒麟上可运行 |
| 单元测试通过 | 组件行为符合当前测试 | 真实 SDK、Milvus 或 500ms 指标通过 |
| Hash/内存模式跑通 | 主链接线正确 | 麒麟 Embedding 验收通过 |
| Kylin strict + Milvus 跑通 | 真实 SDK 与持久化向量链路可用 | 四项指标自动达标，仍需正式跑分 |

## 3. 已知的 V11 环境风险

- 当前虚拟机为银河麒麟 V11 2603，采用不可变核心和 OSTree 软件包保护。
- 直接使用 `apt/dpkg` unpack 曾被 `ostree-pkgs-guard` 拦截。
- 不得为安装开发包而擅自解除 OSTree 保护或破坏系统基线。
- V11 发布说明提到 KARE 历史兼容环境和开明运行环境，但当前证据不足以认定它们是 CoreAI SDK 的唯一官方开发路径。
- SDK 3.0 指南的 AI 章节以银河麒麟 2503 为前提；V11 2603 能否完全复用其安装方式，必须实测。

## 4. 验收阶段与停止线

```text
A. 系统基线记录
  → B. Python + Hash + 内存后端跑通
  → C. 严格 Kylin Embedding 跑通
  → D. 获得真实维度后接 Milvus
  → E. 前后端全链验收
  → F. 标准数据集指标报告
```

上一阶段失败时不要跳到下一阶段。特别是：

- SDK 尚未返回真实维度前，不要固化 Milvus Collection Schema。
- `using_fallback=true` 时，不得记录为 SDK 通过。
- 进程内存后端的检索延迟不得作为比赛 500ms 验收数据。

## 5. 阶段 A：建立系统基线

在安装或修改任何内容前执行：

```bash
mkdir -p "$HOME/mokoa-evidence"

{
  date -Is
  uname -a
  uname -m
  cat /etc/os-release
  python3 --version
  git --version
  free -h
  df -h
} | tee "$HOME/mokoa-evidence/00-system-baseline.txt"
```

额外记录：

- 虚拟机软件及版本；
- CPU 架构、分配核数、内存、磁盘；
- V11 版本和激活状态；
- “设置 → AI 模块管理”页面截图；
- 网络模式（NAT/桥接）及虚拟机 IP。

## 6. 阶段 B：先跑通项目主链

### 6.1 获取代码

```bash
git clone https://codeup.aliyun.com/6a60620d8c4f3693e22016a1/MOKOA.git
cd MOKOA
git checkout master
git pull --ff-only
git rev-parse HEAD | tee "$HOME/mokoa-evidence/01-git-head.txt"
```

### 6.2 建立用户级 Python 环境

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

若 `venv` 不可用或安装被 OSTree 阻止，立即停止，保留原始输出，不要用 `sudo pip`、不要修改系统 Python，由团队确认 KARE/开明/宿主用户环境中的合规方案。

第一次运行可以暂不安装体积较大的本地 BGE 模型依赖：

```bash
grep -v '^sentence-transformers' requirements.txt > /tmp/requirements-vm.txt
python -m pip install -r /tmp/requirements-vm.txt \
  2>&1 | tee "$HOME/mokoa-evidence/02-pip-install.txt"
```

### 6.3 Hash + 内存模式验证

```bash
export OS_AGENT_MEMORY_BACKEND=memory
export OS_AGENT_EMBEDDING_BACKEND=hash

python scripts/smoke_e2e.py \
  2>&1 | tee "$HOME/mokoa-evidence/03-smoke-e2e.txt"
```

通过标准：输出包含 `"passed": true`。

回归测试：

```bash
python -m pytest -q \
  tests/test_kylin_readiness.py \
  tests/test_knowledge.py \
  tests/test_config.py \
  tests/test_preference_orchestrator_wire.py \
  tests/test_api.py::test_health \
  2>&1 | tee "$HOME/mokoa-evidence/04-baseline-tests.txt"
```

启动 API：

```bash
uvicorn api.server:app --host 0.0.0.0 --port 8000 \
  2>&1 | tee "$HOME/mokoa-evidence/05-api-server.txt"
```

另一终端执行：

```bash
curl -i http://127.0.0.1:8000/health
```

必须返回 HTTP 200 和 `{"status":"ok"}`。

## 7. 阶段 C：严格验证 Kylin Embedding

### 7.1 已知 SDK 信息

当前 V11 虚拟机已观察到：

- 运行库：`/usr/lib/x86_64-linux-gnu/libkysdk-coreai-embedding.so.1`；
- 开发包：`libkylin-coreai-embedding-dev`；
- 开发包已下载并解包查看，但尚未安装到 `/usr/include`；
- 曾出现 `COREAI_EMBEDDING_CONNECTION_ERROR`。

SDK 3.0 指南对该错误的定义是“向量化服务连接错误”。因此应检查 AI 子系统、服务、socket/D-Bus 和权限，不要继续盲目搜索 `.onnx` 文件。

### 7.2 动态库与符号检查

```bash
ls -l /usr/lib/x86_64-linux-gnu/libkysdk-coreai-embedding.so.1
ldd /usr/lib/x86_64-linux-gnu/libkysdk-coreai-embedding.so.1
nm -D /usr/lib/x86_64-linux-gnu/libkysdk-coreai-embedding.so.1 \
  | grep -E 'text_embedding|embedding_result' \
  | tee "$HOME/mokoa-evidence/06-sdk-symbols.txt"
```

### 7.3 项目预检

```bash
source .venv/bin/activate

export OS_AGENT_EMBEDDING_BACKEND=kylin
export OS_AGENT_KYLIN_STRICT=1
export KYLIN_EMBEDDING_LIBRARY=/usr/lib/x86_64-linux-gnu/libkysdk-coreai-embedding.so.1

python scripts/kylin_preflight.py \
  --require-kylin \
  --output data/reports/kylin_preflight.json \
  2>&1 | tee "$HOME/mokoa-evidence/07-kylin-preflight.txt"
```

### 7.4 严格 SDK smoke test

```bash
python scripts/smoke_kylin_embedding.py \
  --runs 20 \
  --output data/reports/kylin_embedding.json \
  2>&1 | tee "$HOME/mokoa-evidence/08-kylin-embedding.txt"
```

通过标准：

- `passed=true`；
- `backend=kylin-coreai`；
- `using_fallback=false`；
- 同一批次向量维度一致；
- 向量非空、非零，且不包含 NaN/Inf；
- 报告包含 min/median/max 延迟和模型信息。

## 8. `COREAI_EMBEDDING_CONNECTION_ERROR` 取证清单

若严格测试仍返回连接错误，执行：

```bash
ps aux | grep -Ei 'coreai|embedding|kylin.*ai'
systemctl --type=service | grep -Ei 'coreai|embedding|kylin.*ai'
systemctl --user --type=service | grep -Ei 'coreai|embedding|kylin.*ai'
journalctl --user -b | grep -Ei 'coreai|embedding|connection'
journalctl -b | grep -Ei 'coreai|embedding|connection'
```

将原始输出分别保存，并一同记录：

- AI 模块管理中的子系统状态和截图；
- 当前用户名、组信息；
- 动态库 `ldd` 输出；
- 完整 Python traceback；
- SDK 错误码和错误信息；
- 是否在虚拟机中、是否有 GPU/硬件加速。

## 9. 阶段 D：获得真实维度后再接 Milvus

从 `data/reports/kylin_embedding.json` 读取真实 `dimension`，然后设置：

```bash
export MEMORY_VECTOR_DIM=<真实维度>
export OS_AGENT_MEMORY_BACKEND=milvus
export OS_AGENT_MILVUS_URI=./data/os_agent_memory.db
export OS_AGENT_EMBEDDING_BACKEND=kylin
export OS_AGENT_KYLIN_STRICT=1
```

优先尝试 Milvus Lite。若 V11/CPU 架构不支持对应 wheel，再评估 Standalone 或外部 Milvus，不要为了安装 Docker 破坏麒麟宿主基线。

向量维度变化后，旧 Collection 不可继续使用，必须新建测试库或 Collection。

启动真实服务：

```bash
uvicorn api.server:app --host 0.0.0.0 --port 8000 \
  2>&1 | tee "$HOME/mokoa-evidence/09-real-api-server.txt"
```

## 10. 阶段 E：前后端与持久化验收

最低必测项：

1. `POST /ingest` 可写入多源记忆；
2. `POST /preferences/extract` 能提取偏好；
3. `GET /preferences/{user_id}/profile` 返回结构化画像；
4. 连续写入同一偏好键时返回新版本和 `superseded_memory_id`；
5. `POST /recall` 使用真实向量返回相关记忆；
6. 重启 FastAPI 后长期记忆仍可查询；
7. `POST /forget` 后，目标内容在短期、中期、长期和 staging 中均不可恢复；
8. Vue 前端的偏好画像和冲突页面展示真实 API 数据。

前端不一定要立即安装在虚拟机。可在 Windows 上运行 Vue，并建立 SSH 隧道：

```powershell
ssh -L 8000:127.0.0.1:8000 <用户>@<虚拟机IP>
```

## 11. 阶段 F：比赛指标

| 指标 | 目标 | 必须使用的环境 |
|---|---:|---|
| 偏好提取准确率 | ≥ 85% | 标准标注数据集，报告明确 precision/recall/F1/完全匹配口径 |
| 知识检索召回率 | ≥ 85% | Kylin strict + 真实向量库 |
| 知识检索延迟 | ≤ 500ms | 记录数据规模、预热方式、P50/P95，包含 embedding + search |
| 冲突处理正确率 | ≥ 88% | 标注冲突数据集，不仅是单个 Demo |

真机/虚拟机报告必须说明：

- 系统版本、CPU 架构、核数、内存；
- 是虚拟机还是实体机；
- SDK 软件包版本、动态库路径；
- AI 子系统和模型信息；
- 向量维度；
- Milvus 模式和数据规模；
- 每个指标的数据集版本、命令和原始结果。

## 13. 禁止项

- 禁止解除 OSTree 保护后盲目安装软件包。
- 禁止在系统 Python 中使用 `sudo pip install`。
- 禁止把 Hash/BGE fallback 结果写成麒麟 SDK 结果。
- 禁止在未获得真实向量维度前初始化正式 Collection。
- 禁止只保留截图而不保留命令、返回码和原始文本输出。
- 禁止把“未找到 `.onnx` 文件”解释为“系统没有 Embedding 模型”。
- 禁止将 SDK 指南中的 `kkysdk-coreai-embedding` 直接当成真机 pkg-config 名称；该处可能存在排版或拼写问题，以 `pkg-config --list-all` 和开发包 `.pc` 文件为准。
