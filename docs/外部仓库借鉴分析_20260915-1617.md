## 二、各仓库评价

### 1. wan-wei--shuyi-osagent（宛委·枢忆）— 成熟度最高、最相关 ⭐
- 318 commits，v1.0.0（2026-09-05）；麒麟 V10(SP3) 实测 1872 passed / 7 skipped；6 个 CI workflow（含 `security.yml`）；pytest 251 函数 / 306 参数化；`ruff.toml`、`pytest.ini` 齐备。
- 后端 FastAPI，前端 Vue3，桌面端 Electron（deb/rpm，目标麒麟 V11）；`native/kylin-sdk-bridge` 桥接麒麟 SDK。
- 核心 `backend/app/memoryos/`（治理层约 3.6k 行）+ 9 个前沿记忆系统轻量复现层（14 个 REST 端点）。
- 设计亮点：**可证明删除**（主表 / 全文索引 / 知识图谱边 / 向量引用 / 遗留表 五处逐项取证 + 审计编号 PDF 证书）、**生命周期状态机**（10 态裁决，`forgotten`/`deleted` 不可逆）、**SQLite 触发器不可变账本**、来源卡片 Provenance Card；明确对标 PIPL 第 47 条 / GDPR 第 17 条「被遗忘权」。
- 诚实标注边界：单节点非生产高可用、部分供应商接入为 stub、偏好提取已知语义泄漏。
- 对 MOKOA 价值：MOKOA 已有 `POST /forget` 级联删除（short/mid/Milvus），可借鉴其「五处取证 + PDF 证书」把删除从「执行」升级为「可证明」；其审计账本 / 生命周期状态机可直接映射到 MOKOA 的记忆治理。

### 2. code_nex（NexAgent）— 代码产物成熟度最高 ⭐
- 159 个 `.py`、24 个测试文件、`pyproject.toml`+`uv.lock`+`requirements.txt`、中英文双 README、TODO、LICENSE。
- 11 个专门智能体（协调员 / 知识管理员 / 系统操作员 / 填表员 / PPT / 规划员 / 主管 / 研究员 / 程序员 / 浏览器 / 汇报员），意图识别 + 动态规划路由。
- 含 `kylin-actuator`（麒麟执行器）、`a2a_host/server`（Agent2Agent）、`mcp_host/server`（MCP）、`ocr_tool`、`autofill`；`src/memory/` 下已有 `mem0_store.py`、`kylin_mem0_adapter.py`、`memory_lifecycle.py`、`kylin_embedder.py` 等记忆模块。
- 注意：5 个提交全在同一天（2026-07-13），属一次性批量导入，**过程成熟度低**（无渐进提交史），但**产物成熟度很高**。
- 对 MOKOA 价值：多智能体编排范式、MCP/A2A host/server 实现、麒麟执行器与 OCR 集成、`mem0` 适配器写法可直接对照 MOKOA 的记忆层。

### 3. Project.PIXIU（貔貅）— 设计成熟度最高、零代码
- 259 文件中有 247 个是 `.md`、**无任何源码**（仅 Dockerfile / compose 脚手架），自评「设计阶段」。
- 架构设计很完整：去中心化无中心记忆网络（Gossip 推送 + 反熵对账 + CRDT 合并）、多源融合接入、偏好动态捕捉、**神经-符号混合检索**（BM25 + 向量 ANN + 实体关系图三通道融合，P95 ≤ 500ms）、冲突智能仲裁、自然语言级联遗忘、UKUI 原生 Qt5 悬浮球。
- 对 MOKOA 价值：**纯设计参考**，无代码可抄；但其「神经-符号混合检索」「冲突仲裁」「偏好捕捉 + 版本化」「级联遗忘」与 MOKOA 的检索 / 偏好 / 遗忘诉求几乎一一对应，可作为 MOKOA 记忆架构的设计蓝本（尤其混合检索与冲突仲裁）。

### 4. SuSG2025-KylinAiAssistant — 成熟度最低
- 36 文件，Qt5/C++（`.pro`、`resources.qrc`），含一份课程设计 `.docx` 与 AI SDK 接口 `.pdf`；学生 / 竞赛作品。
- 文本对话 / 语音 / 角色定制，整合麒麟 AI SDK。
- 对 MOKOA 价值：仅「麒麟 SDK 调用 + Qt 桌面集成」可少量借鉴，整体成熟度与相关性最低。

## 四、对 MOKOA 的具体借鉴建议

- **首选深挖 wan-wei**：重点读 `backend/app/memoryos/`、`docs/INNOVATIONS.md`、`docs/MemoryOS-记忆治理层.md`、`docs/ARCHITECTURE.md`、审计报告。把其「可证明删除 / 审计账本 / 生命周期状态机」映射到 MOKOA 既有 `POST /forget`，从「级联删除」升级为「可审计、可证明的遗忘」。
- **对照 code_nex 的记忆层与多智能体**：`src/memory/` 与 MOKOA 短期 / 中期 / Milvus / 偏好层对照；其 MCP/A2A 可参考用于 MOKOA 的工具 / 智能体互联。
- **吸收 PIXIU 的混合检索与冲突仲裁设计**：作为 MOKOA 检索与偏好模块的设计参考。
- **统一借鉴「诚实标注边界」的文档风格**：wan-wei 与 PIXIU 都明确列出已知局限，可作为 MOKOA 文档范式。

## 五、后续动作建议

- 这四个仓库均为**嵌套 .git**（独立仓库）。建议把 `git/` 加入 MOKOA 的 `.gitignore`，避免被当成子目录误提交进 MOKOA。
- wan-wei 体量较大（621 文件），如需长期参照可保留；其余三个较小。
- 若要做功能借鉴（如可证明删除），建议先开 issue / 分支，避免直接 copy 代码：许可证各异——wan-wei 为木兰 PSL v2，code_nex / SuSG 为 MIT，PIXIU 未明示。
